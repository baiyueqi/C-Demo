# LLL 格基约化算法分析与优化研究设计文档

## 1. 项目概述

### 1.1 研究背景

格基约化是现代密码学和计算数论中的基础工具。LLL 算法能够在多项式时间内把一组整数格基变换为较短、较接近正交的格基，因此常用于整数关系发现、背包密码攻击、RSA 部分信息攻击、NTRU 类密码分析、LWE/SIS 格密码参数评估以及 CVP/SVP 近似求解。

本项目围绕 LLL 格基约化算法开展分析与优化研究，重点不是只复现算法流程，而是建立一套能够对不同参数、不同近似 CVP 方法和不同约化算法进行可重复评测的实验框架。

### 1.2 研究目标

1. 理解并实现 Babai 最近平面算法，分析其对格基质量的依赖，并提出可验证的改进方案。
2. 分析 LLL 算法中的核心参数，设计参数扫描实验，比较运行时间、约化质量和数值稳定性。
3. 调研并评测 BKZ、DeepLLL、PotLLL 等更强或更实用的格基约化算法，给出适合课程研究项目的实现路线和对比指标。
4. 结合现代密码学应用场景，形成“算法原理 - 实验设计 - 参数优化 - 改进方向”的完整设计文档。

### 1.3 预期成果

```text
设计文档
  |
  +-- LLL 与 Babai 原理说明
  +-- 参数优化与实验指标
  +-- BKZ / DeepLLL / PotLLL 对比方案

```

## 2. 相关基础

### 2.1 格与格基

给定线性无关向量：

```text
B = [b_1, b_2, ..., b_n], b_i in Z^m
```

它们生成的整数格为：

```text
L(B) = { z_1 b_1 + z_2 b_2 + ... + z_n b_n | z_i in Z }
```

不同的格基可以生成同一个格。格基约化的目标是通过整数可逆变换，把原始基变成短且近似正交的基。

### 2.2 Gram-Schmidt 正交化

LLL 和 Babai 算法都依赖 Gram-Schmidt 正交化。设：

```text
b_i* = b_i - sum(j=1..i-1) mu_i,j b_j*
mu_i,j = <b_i, b_j*> / <b_j*, b_j*>
```

其中：

- `b_i` 是原始基向量；
- `b_i*` 是正交化后的向量；
- `mu_i,j` 表示 `b_i` 在 `b_j*` 方向上的投影系数。

LLL 的交换、尺寸约化和 Lovasz 条件都围绕这些量展开。

### 2.3 LLL 约化条件

一个基通常称为 `(delta, eta)-LLL reduced`，需要满足两个条件。

尺寸约化条件：

```text
|mu_i,j| <= eta, 1/2 <= eta < sqrt(delta)
```

Lovasz 条件：

```text
delta * ||b_{k-1}*||^2 <= ||b_k* + mu_k,k-1 b_{k-1}*||^2
```

等价写法：

```text
(delta - mu_k,k-1^2) * ||b_{k-1}*||^2 <= ||b_k*||^2
```

参数 `delta` 越接近 1，通常输出基质量越高，但交换次数和运行时间也会上升。经典理论中常取 `delta = 3/4`，实际密码分析中常使用更接近 1 的值，例如 `0.99` 或 `0.999`。

## 3. LLL 算法设计

### 3.1 基本流程

```text
Input: basis B = [b_1, ..., b_n], delta, eta
Output: reduced basis B'

1. 计算 Gram-Schmidt 数据
2. k = 2
3. while k <= n:
     对 j = k-1 到 1 进行 size reduction
     如果 Lovasz 条件成立:
         k = k + 1
     否则:
         交换 b_k 和 b_{k-1}
         更新 Gram-Schmidt 数据
         k = max(k-1, 2)
4. 输出 B
```

### 3.2 关键实现点

1. 基向量应保存为整数，保证基变换后仍然生成同一个格。
2. Gram-Schmidt 系数可用 `long double` 作为第一版实现，后续再加入多精度浮点或有理数校验。
3. 每次尺寸约化执行：

```text
b_i = b_i - round(mu_i,j) * b_j
```

4. 交换向量后不应全量重算所有 GSO 数据，优化版本只更新受影响的局部区间。
5. 对高维或大系数输入，应记录数值异常，例如 `NaN`、极小 GSO 范数、整数溢出和不满足最终约化条件的情况。

### 3.3 统计数据

每次运行 LLL 应输出：

| 指标 | 含义 |
| --- | --- |
| `dimension` | 格维数 |
| `ambientDimension` | 向量所在空间维数 |
| `delta` | Lovasz 参数 |
| `eta` | size reduction 参数 |
| `swapCount` | 交换次数 |
| `sizeReductionCount` | 尺寸约化次数 |
| `gsoUpdateCount` | GSO 更新次数 |
| `runtimeMs` | 运行时间 |
| `firstVectorNorm` | `||b_1||` |
| `determinantEstimate` | 格行列式估计 |
| `rootHermiteFactor` | 根 Hermite 因子 |
| `orthogonalityDefect` | 正交缺陷 |
| `validReduced` | 是否通过最终条件检查 |

## 4. Babai 最近平面算法

### 4.1 问题定义

Closest Vector Problem, CVP 的目标是：给定格 `L(B)` 和目标向量 `t`，寻找格点 `v in L(B)`，使得：

```text
||t - v|| = min_{x in L(B)} ||t - x||
```

精确 CVP 在高维中很困难。Babai 最近平面算法使用约化后的格基进行贪心舍入，得到一个近似最近格点。

### 4.2 基本算法

```text
Input: reduced basis B, target t
Output: approximate closest lattice vector v

1. 计算 B 的 Gram-Schmidt 数据
2. r = t
3. for i = n down to 1:
     c_i = round(<r, b_i*> / <b_i*, b_i*>)
     r = r - c_i * b_i
4. v = t - r
5. 输出 v
```

算法质量高度依赖基的约化质量。基越短、越接近正交，逐层舍入越不容易早期出错。

### 4.3 改进方向

#### 4.3.1 先约化再求近似 CVP

对同一目标 `t`，比较以下输入基：

1. 原始随机基。
2. LLL 约化基。
3. 更高 `delta` 的 LLL 约化基。
4. BKZ 或 DeepLLL 约化基。

预期结果：约化越充分，Babai 输出越接近真实最近格点，但预处理成本更高。

#### 4.3.2 多次随机扰动 Babai

基础 Babai 只有一次确定性舍入。可引入小扰动或随机舍入：

```text
c_i = floor(alpha_i) with probability ceil(alpha_i) - alpha_i
c_i = ceil(alpha_i) otherwise
```

其中：

```text
alpha_i = <r, b_i*> / <b_i*, b_i*>
```

重复运行 `R` 次并选择距离最小的候选。该方法能提升部分实例上的成功率，但会增加运行时间，并且需要固定随机种子保证实验可复现。

#### 4.3.3 尾部小块枚举

对最后 `k` 个 Gram-Schmidt 方向，不只取最近整数，而是在小窗口内枚举：

```text
c_i in {round(alpha_i)-w, ..., round(alpha_i)+w}
```

推荐初始参数：

| 参数 | 建议值 |
| --- | --- |
| `tailBlockSize` | 4, 6, 8 |
| `windowRadius` | 1, 2 |
| `maxCandidates` | 1000 到 10000 |

该方法介于 Babai 和枚举算法之间，适合做“低成本改进”的实验。

#### 4.3.4 残差局部搜索

Babai 得到候选 `v` 后，在小范数格向量组合上做局部改进：

```text
v' = v + sum_i e_i b_i, e_i in {-1, 0, 1}
```

只在前若干个短向量或后若干个敏感方向上搜索，避免组合爆炸。

### 4.4 Babai 评测指标

| 指标 | 含义 |
| --- | --- |
| `distance` | `||t - v||` |
| `approxRatio` | `||t - v|| / dist(t, L)`，小维度可用精确枚举求分母 |
| `exactHitRate` | 是否命中真实最近格点 |
| `candidateCount` | 生成候选数量 |
| `runtimeMs` | 运行时间 |
| `preReductionTimeMs` | 预处理约化时间 |

小维度实验中建议用穷举或 sphere enumeration 得到真实 CVP 答案，用于校验 Babai 结果。

## 5. LLL 参数优化方案

### 5.1 待优化参数

| 参数 | 作用 | 取值建议 |
| --- | --- | --- |
| `delta` | Lovasz 条件强度 | `0.75`, `0.90`, `0.95`, `0.99`, `0.999` |
| `eta` | 尺寸约化阈值 | `0.501`, `0.51`, `0.75`，且必须 `< sqrt(delta)` |
| `precision` | GSO 浮点精度 | `double`, `long double`, 多精度 |
| `updateStrategy` | GSO 更新方式 | 全量重算、局部更新、延迟更新 |
| `reductionMode` | 尺寸约化策略 | eager、lazy、deep insertion 扩展 |
| `maxIterations` | 防止异常不终止 | 按维度和输入规模设置上限 |

### 5.2 参数扫描实验

对每组输入格，执行：

```text
for delta in DELTA_VALUES:
  for eta in ETA_VALUES:
    if eta < sqrt(delta):
      run LLL(B, delta, eta)
      record metrics
```

推荐输出为 CSV 或 JSON：

```json
{
  "algorithm": "LLL",
  "dimension": 60,
  "delta": 0.99,
  "eta": 0.51,
  "runtimeMs": 128.4,
  "swapCount": 932,
  "firstVectorNorm": 12345.6,
  "rootHermiteFactor": 1.021,
  "validReduced": true
}
```

### 5.3 优化目标

本项目不应只追求单个指标。建议分成三类目标。

质量优先：

```text
minimize rootHermiteFactor
minimize firstVectorNorm
maximize Babai exactHitRate
```

速度优先：

```text
minimize runtimeMs
minimize swapCount
minimize gsoUpdateCount
```

稳定性优先：

```text
validReduced = true
no overflow
no NaN
results reproducible
```

### 5.4 推荐默认配置

第一版实现推荐：

```text
delta = 0.99
eta = 0.51
number type = int64_t for small experiments
gso type = long double
random seed = fixed
```

原因：

1. `delta = 0.99` 在质量和时间之间比较适合教学实验。
2. `eta = 0.51` 接近严格尺寸约化，便于检查实现正确性。
3. `int64_t + long double` 简单可控，适合先完成小中维实验。
4. 大系数和高维实验后续再切换到 `boost::multiprecision::cpp_int` 或外部格库对照。

## 6. 其它格基约化算法

### 6.1 BKZ 算法

BKZ, Block Korkine-Zolotarev reduction, 可以理解为“在滑动窗口中调用 SVP 子程序”的强约化算法。它比 LLL 更强，但成本随块大小快速上升。

核心参数：

| 参数 | 含义 |
| --- | --- |
| `blockSize beta` | 每次处理的局部块维数 |
| `svpSolver` | 枚举、筛法或近似 SVP |
| `tourCount` | 完整扫描次数 |
| `pruning` | 枚举剪枝策略 |

评测重点：

1. 相同维数下，`beta` 增大时输出质量如何变化。
2. `beta` 增大时运行时间如何增长。
3. BKZ 后的 Babai 成功率是否显著提高。
4. 在密码分析类实例上，是否明显优于 LLL。

推荐课程项目先不从零实现完整 BKZ，可采用两阶段路线：

1. 先实现 mini-BKZ：小块枚举 + LLL 后处理。
2. 再与成熟库输出对比，例如 fplll/fpylll 的 BKZ 结果。

### 6.2 DeepLLL 算法

DeepLLL 对 LLL 的交换操作进行增强。传统 LLL 只交换相邻向量，DeepLLL 允许把当前向量插入到更靠前的位置，从而获得更强的约化效果。

基本思想：

```text
如果 b_k 插入到位置 i 能明显降低局部势能或改善 GSO 长度，
则执行 deep insertion，而不只交换 b_k 和 b_{k-1}。
```

优点：

1. 实践中输出基质量通常优于普通 LLL。
2. 对 Babai 和后续 BKZ 预处理有帮助。

风险：

1. 朴素 DeepLLL 可能运行时间明显增加。
2. 如果插入判据设计不当，可能缺少清晰的多项式时间保证。
3. GSO 更新更复杂，容易引入实现错误。

### 6.3 PotLLL 算法

PotLLL 是 DeepLLL 的一个多项式时间版本。它使用“势能”函数控制插入操作，目标是在提升输出质量的同时保留理论上的终止和复杂度保证。

可把格基势能理解为对 Gram-Schmidt 长度的一种加权乘积。插入操作只有在足够降低势能时才执行。

适合作为本项目的研究点：

1. 与普通 LLL 相比，PotLLL 是否能稳定降低根 Hermite 因子。
2. 与 DeepLLL 相比，PotLLL 是否能控制运行时间。
3. 在 Babai CVP 实验中，PotLLL 预处理是否带来更高命中率。

### 6.4 算法对比表

| 算法 | 核心思想 | 主要参数 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| LLL | 相邻交换 + 尺寸约化 | `delta`, `eta` | 多项式时间、实现简单 | 高维质量有限 |
| Babai | 基于约化基的逐层舍入 | 预处理基、随机次数 | 快速近似 CVP | 依赖基质量 |
| BKZ | 局部块内 SVP 约化 | `beta`, tours, pruning | 约化质量强 | 成本高、实现复杂 |
| DeepLLL | 允许深插入 | 插入深度、判据 | 实践质量较好 | 运行时间可能膨胀 |
| PotLLL | 势能控制的深插入 | `delta`, 势能阈值 | 兼顾质量与理论保证 | 实现和分析更复杂 |

## 7. 现代密码学应用场景

### 7.1 背包密码与子集和问题

低密度子集和问题可构造为格问题。LLL/BKZ 约化后，短向量可能直接泄露原始选择向量。实验可生成：

```text
given weights a_1, ..., a_n
target s = sum x_i a_i, x_i in {0, 1}
```

将其嵌入格基，通过约化搜索含有 `x_i` 结构的短向量。

### 7.2 RSA 部分信息攻击

LLL 是 Coppersmith 小根方法的核心工具之一。对低指数 RSA、部分已知明文、部分已知私钥等问题，可以把小根搜索转化为多项式格基约化问题。

本项目不建议第一阶段完整实现 Coppersmith 攻击，但可以在报告中说明 LLL 如何作为“小根搜索”的基础部件。

### 7.3 LWE/SIS 与后量子密码参数评估

现代格密码通常基于 LWE、Module-LWE、Ring-LWE、SIS 等问题。BKZ 的块大小和根 Hermite 因子常用于估计攻击成本。项目中的 LLL/BKZ 实验可作为理解格密码安全估计的基础。

可设计简化 LWE 实验：

```text
A s + e = b mod q
```

构造 q-ary lattice，观察不同约化强度下短误差向量或秘密向量是否更容易恢复。

### 7.4 NTRU 类密码分析

NTRU 的密钥恢复可转化为寻找特定卷积格中的短向量。BKZ 通常比 LLL 更有实际意义。课程项目可在文档中讨论 NTRU 格结构，不建议第一版从零实现完整 NTRU 攻击。

研究有效性：

1. 参数变化能体现明确的质量和时间权衡。

## 10. 风险与应对

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 浮点误差 | 最终检查不满足 LLL 条件 | 使用 `long double`，增加重算校验，必要时引入多精度 |
| 整数溢出 | 尺寸约化后系数过大 | 小规模用 `int64_t`，扩展实验用 `boost::multiprecision::cpp_int` |
| 实验不可复现 | 同一参数结果不同 | 固定随机种子，保存输入基和目标向量 |
| 指标单一 | 只说明速度或只说明质量 | 同时报告运行时间、RHF、Babai 命中率 |
| 从零实现 BKZ 成本过高 | 进度失控 | 先做 mini-BKZ，再与成熟库结果对照 |
| DeepLLL 不终止或过慢 | 插入次数过多 | 增加插入深度限制和势能阈值，优先研究 PotLLL |

## 11. 阶段计划

### 第一阶段：理论与基线

### 6.2 `src/lattice.hpp` 与 `src/lattice.cpp`

该模块定义格基基础类型和整数向量运算。

```cpp
Integer checkedInteger(__int128 value) {
    if (value < static_cast<__int128>(std::numeric_limits<Integer>::min()) ||
        value > static_cast<__int128>(std::numeric_limits<Integer>::max())) {
        throw std::overflow_error("int64 lattice coefficient overflow");
    }
    return static_cast<Integer>(value);
}
```

### 6.3 `src/gso.hpp` 与 `src/gso.cpp`

该模块实现 Gram-Schmidt 正交化，是 LLL 和 Babai 的公共基础。

核心职责：

1. 计算正交向量 `b_i*`。
2. 计算投影系数 `mu[i][j]`。
3. 记录 `||b_i*||^2`。
4. 支持从指定位置开始的后缀重算，用于减少 GSO 更新量。
5. 检查秩亏和非有限浮点值。

关键代码片段：

```cpp
for (std::size_t j = 0; j < i; ++j) {
    const Real denom = data.squaredNorms[j];
    data.mu[i][j] = dot(toRealVector(basis[i]), data.orthogonal[j]) / denom;
    for (std::size_t col = 0; col < m; ++col) {
        data.orthogonal[i][col] -= data.mu[i][j] * data.orthogonal[j][col];
    }
}
```

### 6.4 `src/lll.hpp` 与 `src/lll.cpp`

该模块实现 LLL 约化主算法。

核心职责：

1. 校验 `delta`、`eta` 参数范围。
2. 执行尺寸约化：

```text
b_k = b_k - round(mu_k,j) * b_j
```

3. 检查 Lovasz 条件，不满足时交换相邻基向量。
4. 统计运行时间、交换次数、尺寸约化次数、GSO 更新量、RHF、正交缺陷。
5. 调用 `isLllReduced` 对最终结果进行二次校验。

关键代码片段：

```cpp
const Real lhs = config.delta * gso.squaredNorms[k - 1];
const Real mu = gso.mu[k][k - 1];
const Real rhs = gso.squaredNorms[k] + mu * mu * gso.squaredNorms[k - 1];

if (lessOrNearlyEqual(lhs, rhs, 1e-14L)) {
    ++k;
    continue;
}

std::swap(basis[k], basis[k - 1]);
```

### 6.5 `src/babai.hpp` 与 `src/babai.cpp`

该模块实现基础 Babai 和三种改进策略。

核心职责：

1. `babaiNearestPlane`：从最后一个 GSO 方向向前舍入。
2. `randomizedBabaiNearestPlane`：对投影系数按小数部分随机选择上下整数。
3. `tailEnumerationBabai`：枚举尾部若干系数附近的小窗口。
4. `localSearchBabai`：在基础 Babai 结果附近做局部系数搜索。
5. 记录距离、候选数和运行时间。

关键代码片段：

```cpp
for (std::size_t reverseIndex = basis.size(); reverseIndex > 0; --reverseIndex) {
    const std::size_t i = reverseIndex - 1;
    const Real alpha = dot(residual, gso.orthogonal[i]) / gso.squaredNorms[i];
    const Integer coefficient = roundRealToInteger(alpha);
    coefficients[i] = coefficient;
    subtractCoefficient(residual, basis[i], coefficient);
}
```

## 7. 源程序解释

### 7.1 总体流程

程序执行流程如下：

```text
读取命令行参数
  |
  +-- 生成固定随机种子的整数格基
  |
  +-- 根据实验类型调用对应算法
  |     |
  |     +-- LLL 参数扫描
  |     +-- Babai 对比
  |     +-- 高级约化对比
  |
  +-- 统计质量、速度、稳定性指标
  |
  +-- 输出到终端、CSV 或 Markdown
```

### 7.2 LLL 实现解释

LLL 的核心循环从第二个基向量开始。对当前向量 `b_k`，先从 `k-1` 到 `0` 做尺寸约化，使 `|mu[k][j]| <= eta`。然后检查 Lovasz 条件：

```text
delta * ||b_{k-1}*||^2 <= ||b_k*||^2 + mu[k][k-1]^2 * ||b_{k-1}*||^2
```

如果条件成立，继续处理下一个向量；否则交换 `b_k` 和 `b_{k-1}`，并回退下标继续检查。程序提供两种 GSO 更新策略：

1. `full`：每次变化后重新计算全部 GSO 数据，逻辑简单但开销大。
2. `suffix`：只从受影响位置开始重算后缀，减少重复计算。

最终用 `isLllReduced` 重新计算 GSO 并检查所有 size reduction 条件和 Lovasz 条件，防止中间统计误差掩盖错误。

### 7.3 Babai 实现解释

Babai 最近平面算法先计算 GSO 数据，然后从最后一个基向量向前处理目标残差。每一步计算目标在当前正交方向上的投影系数，并取最近整数作为该方向的格系数。

基础 Babai 速度快，但只有一个候选。为了观察改进空间，程序实现了三种扩展：

1. 随机舍入：按投影系数的小数部分随机选择上下整数，多轮运行取最优。
2. 尾部枚举：对最后若干维的系数在小窗口内枚举，其余维度仍用 Babai 舍入。
3. 局部搜索：以基础 Babai 的系数为中心，在若干个方向上做小范围搜索。

### 7.4 高级约化实现解释

高级约化模块不是完整工业级实现，而是为了课程实验对比设计的轻量原型。

1. mini-BKZ：在小块内枚举短向量组合，若能显著缩短块首向量，则替换并重新 LLL。
2. DeepLLL post-pass：尝试把当前向量插入到更靠前的位置，如果 RHF 改善超过阈值则接受。
3. PotLLL post-pass：计算 GSO 势能，只有当插入使势能足够下降时才接受。

这三个方法都保留 `maxCandidates`、`maxInsertDepth`、`maxPasses` 等限制，防止课程实验中出现组合爆炸或长时间不终止。

## 8. 调试过程中发现的问题与解决办法

### 8.1 GSO 更新后数据不一致

问题：LLL 中执行尺寸约化或交换后，如果继续使用旧的 `mu` 和 `b_i*`，Lovasz 判断会基于过期数据，可能导致错误交换或最终校验失败。

解决办法：每次修改基向量后立即刷新 GSO。程序提供 `full` 和 `suffix` 两种策略，并在统计中记录 `gsoUpdateCount`。最终再用 `isLllReduced` 完整校验输出。

### 8.2 浮点误差导致边界条件误判

问题：Lovasz 条件中涉及浮点乘法和平方范数，`long double` 在边界情况下可能出现极小误差，导致本应通过的条件被判为失败。

解决办法：实现 `lessOrNearlyEqual`，用相对容差比较左右两侧，并在最终校验中使用统一容差。

### 8.3 随机格可能出现秩亏或数值异常

问题：完全随机矩阵在小概率下可能秩亏，Gram-Schmidt 的某个正交范数接近 0，导致除零、`NaN` 或无穷大。

解决办法：随机基生成时构造非零对角线以保证满秩，再进行有限次数行混合；GSO 模块中加入 `kRankTolerance` 和 `hasFiniteGso` 检查，发现异常立即返回错误。

### 8.4 整数行变换可能溢出

问题：LLL 尺寸约化会执行 `b_i = b_i - q b_j`，当系数较大或维度较高时可能超过 `int64_t` 范围。

解决办法：在 `lattice.cpp` 中使用 `__int128` 做中间计算，并通过 `checkedInteger`、`checkedAdd`、`checkedMultiply` 显式检查溢出。当前实验限制 `coefficientBits <= 32`，后续大规模实验应切换到 `boost::multiprecision::cpp_int`。

### 8.5 高级约化候选数增长过快

问题：mini-BKZ 块枚举和 Babai 尾部枚举都可能随窗口半径和块大小指数增长。

解决办法：为相关算法加入 `maxCandidates` 参数；递归枚举过程中一旦达到候选上限立即停止。报告中同时记录候选数，避免只看质量不看代价。

### 8.6 小规模实例难以体现高级算法优势

问题：在 5 到 8 维随机格上，普通 LLL 已经能得到较好结果，mini-BKZ、DeepLLL 和 PotLLL 很可能找不到进一步改进。

解决办法：报告中将该现象作为实验结论说明，并建议后续加入更高维、近相关向量格、q-ary 格和子集和格，以观察高级算法的质量优势。

## 9. 实验总结

本项目完成了 LLL 格基约化、Babai 最近平面、参数扫描和高级约化原型的一体化实验框架。实际测试表明：

1. 程序能够在 `nix develop` 环境下独立构建并通过三组小维度单元测试。
2. LLL 输出满足最终约化条件，参数扫描 30 组实验全部通过校验。
3. `suffix` GSO 更新策略能显著减少 GSO 更新量，适合作为默认实现。
4. Babai 改进算法在简单小维实例中没有改善距离，但候选数和代价变化清晰，实验框架可用于后续困难实例。
5. 高级约化原型在本次小规模实验中未改善 RHF，但验证了算法流程和结果输出接口。

后续改进方向：

1. 增加更多困难测试数据，例如近相关格、q-ary 格、子集和格。
2. 在更高维度下重复参数扫描，并绘制 `delta-runtime`、`delta-RHF`、Babai 命中率等图表。
3. 引入 `boost::multiprecision::cpp_int` 或 fplll/fpylll，对比完整 BKZ 的真实密码分析效果。
4. 将 CSV 结果导入 Jupyter Notebook，生成更直观的图形化实验结果。
