# 项目总览与交付

## 课题定位

本课设是 CrackMe 逆向工程综合实践，不是单纯编写汇编程序。目标是从 Crackmes.one 选择 Easy、Medium、Hard 三个难度的练习程序，通过静态分析、动态调试、汇编语义理解和算法还原，证明能够读懂二进制验证逻辑，并给出破解方案、Keygen、脚本或补丁。

评分重点是过程证据和正确性。报告不能只给最终答案，需要展示从样本识别、字符串定位、函数定位、汇编理解、动态调试到最终验证的完整链路。

## 最终目标

1. 选择 3 个 CrackMe：
   - Easy：1-2 级，1 题。
   - Medium：3 级，1 题。
   - Hard：4 级及以上，1 题。
2. 三题尽量保持同一组合方向：
   - 组合 A：算法 + 反调试。
   - 组合 B：数据处理 + 混淆。
   - 组合 C：综合实战。
3. 每题完成：
   - 程序功能分析。
   - 字符串定位。
   - 关键函数分析。
   - 汇编代码还原为伪代码。
   - 动态调试验证。
   - 破解、补丁、Keygen 或脚本实现。
   - 至少 3 组验证结果。
4. 完成三题综合对比：
   - 难度差异。
   - 技术点差异。
   - 分析方法差异。
   - 时间成本。

## 样本与工具

样本只使用授权 CrackMe 练习程序，不分析真实商业软件。样本信息、URL、哈希和本地路径集中记录在：

```text
Assembly/docs/样本清单.md
```

主要工具：

- Detect It Easy：识别文件类型、架构、编译器、壳。
- IDA Free / Ghidra：静态分析、字符串交叉引用、函数命名、伪代码。
- x64dbg：动态调试、断点验证、寄存器和内存截图。
- Python：Keygen、验证脚本和辅助计算。

## 标准工作流

1. 选题归档：
   - 记录题目名称、URL、作者、难度、平台、架构。
   - 保存原始压缩包或二进制。
   - 计算 SHA256，避免版本混乱。
2. 初始识别：
   - 使用 Detect It Easy 查看架构、位数、编译器、壳和可疑保护。
   - 记录入口点、导入表、明显字符串。
3. 静态分析：
   - 从字符串交叉引用进入关键函数。
   - 标注输入读取、比较、循环、编码、反调试等逻辑。
4. 汇编理解与伪代码还原：
   - 逐段解释关键汇编。
   - 将核心校验逻辑还原成 C/Python 风格伪代码。
5. 动态调试：
   - 使用 x64dbg 设置断点。
   - 重点断在输入读取、字符串比较、校验函数、反调试 API。
   - 截图包含断点位置、寄存器、栈、内存或分支结果。
6. 破解或还原实现：
   - 可选择正确输入、patch、Keygen 或自动化脚本。
   - 优先写脚本或 Keygen，因为更能证明算法理解。
7. 验证：
   - 每题至少给出 3 组输入/输出验证。
   - 说明验证结果为什么能证明算法正确。
8. 综合整理：
   - 按题目分别成章。
   - 最后用表格对比三题技术点、难度、方法和时间成本。
