# 截图与脚本指南

## 截图目录

报告截图按题目和工具分类：

```text
Assembly/screenshots/
├── easy/
│   ├── die/
│   ├── ida/
│   ├── x64dbg/
│   └── run/
├── medium/
│   ├── die/
│   ├── ida/
│   ├── x64dbg/
│   └── run/
└── hard/
    ├── die/
    ├── ida/
    ├── x64dbg/
    └── run/
```

报告中每张截图都需要编号和文字说明，不能只贴图。

## 截图类型

- `die/`：Detect It Easy 基本识别截图，用于证明文件类型、位数、架构、编译器和是否加壳。
- `ida/`：IDA/Ghidra 静态分析截图，用于证明字符串定位、交叉引用、关键函数、算法循环和伪代码。
- `x64dbg/`：动态调试截图，用于证明断点命中、寄存器值、栈/内存内容和成功/失败分支。
- `run/`：普通运行结果截图，用于证明脚本或 Keygen 生成的数据在程序中实际通过。

## Windows 路径注意事项

从 x64dbg 或 CMD 运行样本时，尽量把 exe 复制到 Windows 本地路径，例如：

```text
C:\Temp\KeygenMe_3_SWD\KeygenMe_3_SWD.exe
```

不要直接从 `\\wsl.localhost\...` 运行需要调用 `cmd.exe` 的程序。Windows CMD 不支持把 UNC 路径作为当前目录，可能出现：

```text
UNC 路径不受支持。默认值设为 Windows 目录。
```

这个报错通常来自程序最后调用 `pause`，不一定代表校验失败，但会干扰运行结果截图。

## 脚本目录

脚本、Keygen、验证器或补丁脚本放在：

```text
Assembly/scripts/
```

现有脚本：

- `easy_verify.py`：Easy 题验证脚本。
- `medium_keygen.py`：Medium 题 Keygen。

每个脚本在报告中需要说明：

- 输入是什么。
- 输出是什么。
- 如何运行。
- 对应哪一个题目。
- 结果如何验证。

## Medium 截图采集步骤

样本路径：

```text
Assembly/binaries/medium_keygenme_3_swd/extracted/KeygenMe_3_SWD.exe
```

Keygen 脚本：

```bash
python3 Assembly/scripts/medium_keygen.py Alice
```

### 1. DIE 基本信息

目标：证明样本类型、架构、编译器和是否加壳。

步骤：

1. 打开 Detect It Easy。
2. 将 `KeygenMe_3_SWD.exe` 拖入 DIE。
3. 确认显示 `PE64` / `Console` / `x86-64` 等基本信息。
4. 查看是否有明显 packer 标识；若无，报告中写“未见明显加壳”。
5. 截图保存为：

```text
Assembly/screenshots/medium/die/01_die_basic.png
```

### 2. IDA 字符串窗口

目标：证明从字符串定位主流程。

步骤：

1. 用 IDA 打开 `KeygenMe_3_SWD.exe`。
2. 等待自动分析完成。
3. 打开 `View -> Open subviews -> Strings`。
4. 找到并框选或高亮以下字符串：
   - `0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ`
   - `KeygenMe No 3`
   - `Username: `
   - `Secret code: `
   - `Verification PIN: `
5. 截图保存为：

```text
Assembly/screenshots/medium/ida/01_strings_window.png
```

### 3. IDA 主交互流程

目标：展示程序读取三项输入并调用格式校验函数。

步骤：

1. 在 Strings 窗口双击 `Username: `。
2. 按 `X` 查看交叉引用，跳转到主流程附近。
3. 定位到 `0x140002BD0` 附近。
4. 建议重命名：
   - `0x140002BD0` -> `main_interaction`
   - `0x140001E30` -> `validate_username`
   - `0x140001EC0` -> `validate_secret_format`
   - `0x140001F80` -> `validate_pin_format`
5. 截图中应包含：
   - `0x140002C41` 读取 Username
   - `0x140002CAF` 读取 Secret code
   - `0x140002D08` 读取 Verification PIN
   - 对 `0x140001EC0` 和 `0x140001F80` 的调用
6. 截图保存为：

```text
Assembly/screenshots/medium/ida/02_main_interaction.png
```

### 4. IDA Secret Code 算法

目标：展示用户名如何生成 Secret code 三段。

步骤：

1. 跳转到 `0x140002100`。
2. 建议重命名为 `verify_secret_code`。
3. 找到 `0x140002300` 到 `0x140002399` 的用户名遍历循环。
4. 找到 `0x14000239E` 到 `0x1400023F0` 的三段目标值计算。
5. 截图中最好包含以下常量：
   - `0x5A5A`
   - `0xB640`，即 `46656`
   - `0x39AA400`，即 `60466176`
   - `0x539`，即 `1337`
6. 截图保存为：


### 5. IDA PIN 算法

目标：展示 PIN 的哈希混合与最终比较逻辑。

步骤：

1. 跳转到 `0x1400025A0`。
2. 建议重命名为 `generate_pin_candidate`。
3. 找到 `0x1400026AA` 附近的初始常量：
   - `0xA3B1C2D3`
   - `0x1F2E3D4C`
4. 找到 `0x1400026C9` 到 `0x140002808` 的循环。
5. 截图中最好包含：
   - `rol32` 调用 `0x1400020A0`
   - `ror32` 调用 `0x1400020D0`
   - 常量 `0x9E3779B9`
   - 常量 `0x7F4A7C15`
6. 再跳转到 `0x140002910`，截图 PIN 比较逻辑。

### 6. x64dbg 动态验证

目标：证明脚本生成值能走到成功分支。

准备一组输入。程序会先把用户名转成大写再参与算法，因此 `Alice` 对应的是 `ALICE` 的计算结果：

```text
Username: Alice
Secret code: 0IMB-040EG-YZL
Verification PIN: 775865310
```

步骤：

1. 用 x64dbg 打开 `KeygenMe_3_SWD.exe`。
2. 在模块加载完成后，设置断点。若 ASLR 导致绝对地址无效，用 `keygenme_3_swd.exe:$RVA` 形式。
3. 建议断点：
   - `keygenme_3_swd.exe:$2DD9`，调用 Secret code 校验。
   - `keygenme_3_swd.exe:$2DDE`，Secret code 校验结果判断。
   - `keygenme_3_swd.exe:$2FAE`，调用 Verification PIN 校验。
   - `keygenme_3_swd.exe:$2FB3` 或 `$2FB6`，PIN 校验结果判断。
4. 运行程序，输入上方 `Alice` 的三项值。
5. 在 `$2DDE` 断下时，观察 `EAX != 0`，说明 Secret code 校验通过。
6. 在 `$2FB3` 断下时，可按一次 `F8` 执行 `movzx eax, al`，再观察 `EAX != 0`，说明 PIN 校验通过。
7. 截图保存为：

```text
Assembly/screenshots/medium/x64dbg/01_secret_code_success_branch.png
Assembly/screenshots/medium/x64dbg/02_pin_success_branch.png
```
