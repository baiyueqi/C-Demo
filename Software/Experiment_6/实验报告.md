## 四、程序基本信息

`SSCM.exe` 是一个 MFC 图形界面程序，使用 Visual C++ 编译。程序要求输入用户名和注册码，注册码格式为：

```text
XXXXX-XXXXX-XXXXX-XXXXX-XXXXX
```

即 5 组、每组 5 个字符，共 25 个字符，组与组之间用连字符 `-` 分隔。

`SSCM.pdb` 是程序的符号文件，其中包含函数名、变量名等调试信息。通过分析 PDB，可以发现程序中的关键函数：

```text
CSSCMDlg::OnBnClicked
CSSCMDlg::func3
CSSCMDlg::func4
func1
func2
```

这些函数直接对应注册码的生成与校验流程。

## 五、保护机制分析过程

### 1. 定位关键函数

通过 PDB 符号和反汇编，定位到以下关键函数：

| 函数 | 作用 |
| --- | --- |
| `CSSCMDlg::OnBnClicked` | 按钮点击处理，调用验证逻辑 |
| `CSSCMDlg::func4` | 校验用户名和注册码格式 |
| `CSSCMDlg::func3` | 根据用户名生成校验值 |
| `func1` | RC4 对称加密/解密 |
| `func2` | ROT13 字符变换 |

### 2. 格式校验逻辑

`func4` 的校验规则为：

1. 用户名长度必须为 11。
2. 用户名每一位必须是数字 `0` 到 `9`。
3. 注册码长度必须为 29。
4. 注册码的第 6、12、18、24 个字符必须为连字符 `-`。
5. 去掉 4 个连字符后，注册码长度为 25。

### 3. 注册码生成算法

程序使用了一段固定消息：

```text
软件安全实验课程-1922X1-2
```

该消息的 GBK 编码为 26 字节。程序以用户名为密钥，对这段消息执行 RC4 加密，取前 25 个字节，再按以下规则映射成字符：

```text
if 字节值 > 0xC0:
    字符 = '0' + (字节值 + 0x17) % 10
else:
    字符 = 'A' + (字节值 + 0x17) % 26
```

这样得到一个 25 个字符的中间串 `S`。

随后计算中间串的校验和：

```text
checksum = DWORD(S[4..7])
         + DWORD(S[8..11])
         + DWORD(S[12..15])
         + DWORD(S[16..19])
         + DWORD(S[20..23])
```

其中 `DWORD` 按小端序解释。

用户输入的注册码去掉连字符后，先经过 `func2`，即 ROT13 字母变换，再按同样方法计算校验和。如果两个校验和相等，则提示注册成功。

也就是说，注册码是中间串 `S` 的 ROT13 逆变换结果，再按 5 个字符一组插入连字符。

### 4. 算法验证

用题目给出的示例验证算法：

```text
用户名：20241003101
计算注册码：LA3FC-N3FFL-F5R5N-U9WOY-KUCEH
```

计算结果与题目示例完全一致，说明算法还原正确。

## 七、软件保护机制安全性分析

### 1. 该保护机制存在的问题

该保护机制存在以下明显问题：

1. 验证逻辑完全在本地完成，程序可以直接离线分析和破解。
2. 程序附带了 `SSCM.pdb`，泄露了大量函数名、变量名和调试信息，极大降低了分析难度。
3. 注册码生成算法完全可逆，攻击者能够根据用户名自行计算注册码。
4. 用户名与注册码之间是确定性的单向映射，算法没有引入足够强的密钥或随机性。
5. 关键算法 `func1` 使用 RC4，且密钥直接使用用户名，安全强度不足。
6. 注册码只进行格式检查和校验和比较，攻击者可以绕过比较跳转直接实现破解。
7. 没有服务器验证、数字签名或机器绑定等机制，注册码可以随意传播和复用。

### 2. 改进建议

1. 不要在发布版本中附带 PDB 或任何调试符号。
2. 关键算法不要完全依赖本地可逆计算，应使用非对称加密和数字签名。
3. 将注册码验证放到服务端，客户端只提交用户名和注册码。
4. 使用 RSA/ECDSA 等算法对授权信息进行签名，防止伪造。
5. 增加反调试、反 dump、反篡改和代码混淆保护。
6. 将用户名、机器指纹、产品版本等绑定到授权信息中。
7. 对关键常量进行加密或混淆，避免固定消息直接暴露。
8. 采用一次性激活、在线吊销和授权有效期等机制。

## 八、实验总结

通过本次实验，我完成了对 `SSCM.exe` 注册码保护机制的逆向分析，定位了注册码验证流程，还原了 RC4 加密、ROT13 变换和校验和比较算法，并成功计算出自己学号对应的注册码。

实验说明，仅依赖本地可逆算法和格式校验的注册码保护机制非常脆弱。配合 PDB 符号文件，攻击者能够快速还原算法并生成任意用户名的注册码。软件保护应采用服务器验证、非对称签名、代码混淆和反调试等多层防护手段。

## 附：注册码计算参考代码

```python
MAGIC = bytes([
    0xC8, 0xED, 0xBC, 0xFE, 0xB0, 0xB2, 0xC8, 0xAB,
    0xCA, 0xB5, 0xD1, 0xE9, 0xBF, 0xCE, 0xB3, 0xCC,
    0x2D, 0x31, 0x39, 0x32, 0x32, 0x58, 0x31, 0x2D,
    0x32, 0x00
])

def rc4(key, data):
    s = list(range(256))
    j = 0
    key = bytes(key, 'ascii')
    for i in range(256):
        j = (j + s[i] + key[i % len(key)]) & 0xff
        s[i], s[j] = s[j], s[i]
    out = []
    i = j = 0
    for b in data:
        i = (i + 1) & 0xff
        j = (j + s[i]) & 0xff
        s[i], s[j] = s[j], s[i]
        out.append(b ^ s[(s[i] + s[j]) & 0xff])
    return bytes(out)

def make_serial(username):
    out = rc4(username, MAGIC)[:25]
    chars = []
    for b in out:
        if b > 0xc0:
            chars.append(chr(ord('0') + (b + 0x17) % 10))
        else:
            chars.append(chr(ord('A') + (b + 0x17) % 26))
    s = ''.join(chars)

    def rot13(text):
        a = 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz'
        b = 'NOPQRSTUVWXYZABCDEFGHIJKLMnopqrstuvwxyzabcdefghijklm'
        return text.translate(str.maketrans(a, b))

    raw = rot13(s)
    return '-'.join(raw[i:i+5] for i in range(0, 25, 5))

print(make_serial('20241001655'))
# 输出：FZNOJ-P37IT-U5B36-30418-LHJL5
```
