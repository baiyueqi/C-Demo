# 软件安全测试实验报告

## 实验项目：软件安全测试

## 实验名称：静态代码分析与安全缺陷检测

---

## 一、实验目的

1. 理解静态代码分析的基本原理，掌握利用开发环境内置工具进行安全缺陷检测的基本流程。
2. 能够识别并定位 C 语言典型内存安全缺陷：缓冲区溢出、空指针引用、内存泄漏、数组越界、未初始化变量使用、释放后使用。
3. 能够识别并定位 Java 典型安全缺陷：SQL 注入、硬编码敏感信息、空指针异常、资源泄露。
4. 掌握常见安全缺陷的修复方法，形成安全编码意识与规范。
5. 熟练使用本地工具完成代码编写、缺陷扫描、问题定位与修复验证。

## 三、实验原理

静态代码分析是在不运行程序的前提下，通过词法分析、语法分析、控制流分析、数据流分析等技术，对源代码进行扫描，识别潜在的安全缺陷、编码不规范问题与漏洞。

- C 语言直接操作内存与指针，缺乏运行时边界检查，容易出现缓冲区溢出、空指针引用、内存泄漏、数组越界、未初始化变量使用、释放后使用等安全缺陷。
- Java 语言具有虚拟机内存管理与异常处理机制，但仍存在 SQL 注入、空指针异常、硬编码密码、资源泄漏、XSS 跨站脚本等业务与编码缺陷。

本实验使用 `clang -Wall -Wextra -Wpedantic` 做编译期检查，使用 `clang --analyze` 和 `clang-tidy` 做路径敏感分析；Java 使用 IntelliJ IDEA Inspect Code 或 `javac -Xlint:all`。

### 4.1 编写缺陷代码

`vulnerable.c` 缺陷代码：

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* 1. 缓冲区溢出：目标缓冲区过小，且使用不安全的 strcpy */
void vuln_buffer_overflow(void)
{
    char buf[8];
    strcpy(buf, "This string is much longer than eight bytes");
    printf("buffer_overflow: %s\n", buf);
}

/* 2. 空指针引用：未判空就解引用 */
void vuln_null_deref(void)
{
    int *p = NULL;
    *p = 42;
    printf("null_deref: %d\n", *p);
}

/* 3. 内存泄漏：动态分配后未释放 */
void vuln_memory_leak(void)
{
    char *p = (char *)malloc(32);
    strcpy(p, "leaked memory");
    printf("memory_leak: %s\n", p);
}

/* 4. 数组越界：访问下标等于数组长度的位置 */
void vuln_array_oob(void)
{
    int arr[5] = {1, 2, 3, 4, 5};
    printf("array_oob: %d\n", arr[5]);
}

/* 5. 未初始化变量：读取未赋值的局部变量 */
void vuln_uninitialized(void)
{
    int value;
    if (value > 0)
    {
        printf("uninitialized: positive\n");
    }
}

/* 6. 释放后使用：free 之后再次访问原指针 */
void vuln_use_after_free(void)
{
    char *p = (char *)malloc(10);
    strcpy(p, "hello");
    free(p);
    printf("use_after_free: %s\n", p);
}

int main(int argc, char **argv)
{
    if (argc > 1 && strcmp(argv[1], "run") == 0)
    {
        vuln_buffer_overflow();
        vuln_null_deref();
        vuln_memory_leak();
        vuln_array_oob();
        vuln_uninitialized();
        vuln_use_after_free();
    }

    printf("vulnerable demo: pass 'run' to execute all vulnerable paths.\n");
    return 0;
}
```

### 4.4 修复缺陷

C 修复程序见 [c/fixed.c](c/fixed.c)，Java 修复程序见 [java/Fixed.java](java/Fixed.java)。

`fixed.c` 修复代码：

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* 1. 修复缓冲区溢出：使用 snprintf 并限制写入长度 */
void fixed_buffer_overflow(void)
{
    const char *long_text = "This string is much longer than eight bytes";
    char buf[8];
    snprintf(buf, sizeof(buf), "%s", long_text);
    printf("buffer_overflow_fixed: %s\n", buf);
}

/* 2. 修复空指针引用：解引用前判空 */
void fixed_null_deref(void)
{
    int value = 42;
    int *p = &value;
    if (p != NULL)
    {
        printf("null_deref_fixed: %d\n", *p);
    }
    else
    {
        printf("null_deref_fixed: pointer is null\n");
    }
}

/* 3. 修复内存泄漏：使用完毕及时释放 */
void fixed_memory_leak(void)
{
    char *p = (char *)malloc(32);
    if (p == NULL)
    {
        return;
    }
    snprintf(p, 32, "%s", "released memory");
    printf("memory_leak_fixed: %s\n", p);
    free(p);
}

/* 4. 修复数组越界：下标严格限制在 [0, 4] */
void fixed_array_oob(void)
{
    int arr[5] = {1, 2, 3, 4, 5};
    for (int i = 0; i < 5; ++i)
    {
        printf("array_oob_fixed[%d] = %d\n", i, arr[i]);
    }
}

/* 5. 修复未初始化变量：声明时显式初始化 */
void fixed_uninitialized(void)
{
    int value = 0;
    if (value > 0)
    {
        printf("uninitialized_fixed: positive\n");
    }
    else
    {
        printf("uninitialized_fixed: non-positive\n");
    }
}

/* 6. 修复释放后使用：在释放前完成访问，释放后置空 */
void fixed_use_after_free(void)
{
    char *p = (char *)malloc(10);
    if (p == NULL)
    {
        return;
    }
    snprintf(p, 10, "%s", "hello");
    printf("use_after_free_fixed: %s\n", p);
    free(p);
    p = NULL;
}

int main(void)
{
    fixed_buffer_overflow();
    fixed_null_deref();
    fixed_memory_leak();
    fixed_array_oob();
    fixed_uninitialized();
    fixed_use_after_free();
    return 0;
}
```

`Fixed.java` 修复代码：

```java
import java.io.BufferedReader;
import java.io.FileReader;
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;

public class Fixed {
    public static void sqlInjection(Connection conn, String name) throws Exception {
        String query = "SELECT * FROM users WHERE name = ?";
        try (PreparedStatement ps = conn.prepareStatement(query)) {
            ps.setString(1, name);
            try (ResultSet rs = ps.executeQuery()) {
                while (rs.next()) {
                    System.out.println(rs.getString("name"));
                }
            }
        }
    }

    public static void hardcodedPassword() {
        String password = System.getenv("DB_PASSWORD");
        if (password == null || password.isEmpty()) {
            System.out.println("DB_PASSWORD is not configured");
            return;
        }
        System.out.println("password loaded from environment");
    }

    public static void nullPointer() {
        String text = System.getenv("SAMPLE_TEXT");
        if (text != null) {
            System.out.println(text.length());
        } else {
            System.out.println("SAMPLE_TEXT is not configured");
        }
    }

    public static void resourceLeak() throws Exception {
        try (BufferedReader reader = new BufferedReader(new FileReader("input.txt"))) {
            System.out.println(reader.readLine());
        }
    }

    public static void main(String[] args) throws Exception {
        System.out.println("Fixed demo");
        hardcodedPassword();
        nullPointer();
        resourceLeak();
    }
}
```

## 六、实验思考题

### 1. 静态代码分析能否发现所有安全漏洞？为什么？

不能。静态代码分析只能发现可由词法、语法、控制流和数据流分析推导出的浅层或局部缺陷，例如明显的缓冲区溢出、空指针、未初始化变量和资源未关闭等。它无法完整证明程序语义正确性，也不能发现依赖运行时输入、业务逻辑、权限控制、第三方组件、配置错误或复杂多线程时序的深层漏洞。此外，静态分析可能存在漏报和误报，因此必须结合动态测试、模糊测试和人工代码审计。

### 2. C 语言为什么更容易出现内存安全漏洞？

C 语言直接暴露内存地址和指针，允许任意地址读写，却没有自动边界检查和垃圾回收。数组不会自动记录长度，字符串通常以 `'\0'` 结束，函数如 `strcpy`、`gets`、`sprintf` 不检查目标缓冲区大小；动态内存必须由程序员手动释放，释放后也不阻止继续使用原指针；局部变量不会自动初始化。这些特性使缓冲区溢出、数组越界、内存泄漏、释放后使用等缺陷更容易发生。

### 3. Java 中如何有效防止 SQL 注入？

核心方法是使用参数化查询，将 SQL 结构固定，用户输入只作为绑定参数传入，例如：

```java
String query = "SELECT * FROM users WHERE name = ?";
try (PreparedStatement ps = conn.prepareStatement(query)) {
    ps.setString(1, name);
    try (ResultSet rs = ps.executeQuery()) {
        // 处理结果
    }
}
```

还应遵守：不拼接 SQL；对输入做白名单校验；使用 ORM 框架时避免拼接 HQL/JPQL；为数据库账号配置最小权限；对异常和日志进行脱敏，避免泄露 SQL 细节。

### 4. 什么是释放后使用（UAF）？如何避免？

释放后使用是指程序释放某块动态内存后，原指针仍然保留，并在后续代码中继续通过该指针读写内存。此时内存可能已被分配器回收或重新分配给其他对象，继续使用会导致数据篡改、信息泄露、崩溃甚至被攻击者利用执行任意代码。

避免方法：

1. 释放前完成所有必要访问。
2. 释放后立即将指针置为 `NULL`。
3. 遵循对象所有权和生命周期约定，避免多个指针指向同一块内存。
4. 使用智能指针或自动内存管理机制。
5. 借助静态分析和内存安全检测工具（如 ASan、Valgrind）在测试阶段发现 UAF。

### 5. 资源未关闭长期运行会对系统造成什么影响？

长期运行中，文件、网络连接、数据库连接、句柄等资源未关闭会导致资源泄漏。进程占用的文件描述符、内存、连接池项会持续增长，最终可能耗尽系统文件描述符或内存，导致无法打开新文件、无法建立新连接、程序变慢、崩溃，甚至影响同主机其他进程。数据库连接长期不关闭还会占用服务端连接数，拖垮数据库服务。

## 七、实验总结

通过本次实验，掌握了静态代码分析的基本流程，理解了编译期告警、路径敏感分析和 IDE Inspection 的差异。实验中通过 6 个 C 缺陷示例和 4 个 Java 缺陷示例，完成了“编写缺陷代码 -> 扫描定位 -> 分析原因 -> 修复 -> 复扫验证”的完整闭环。

最重要的体会是：工具只能辅助发现浅层和局部缺陷，不能替代人工审计。安全编码必须从源头遵循初始化、判空、边界检查、资源关闭、参数化查询和敏感信息保护等原则。修复后代码不仅要让工具无告警，还要理解每处告警对应的真实风险，避免仅做表面抑制。
