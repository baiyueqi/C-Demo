# 软件安全实验：恶意软件典型行为分析 实验报告

## 一、实验基本信息

- 实验项目：恶意软件分析与防治
- 实验名称：恶意软件典型行为分析
- 实验环境：Windows 10/11、Visual Studio 2013+、Sysinternals 工具套件（Process Explorer、Process Monitor、TCPView、Strings、CFF Explorer）
- 分析对象：`malware_sim.exe`（教学用、无破坏性的模拟恶意代码）
- 实验方式：静态分析（文件属性 / PE 结构 / 字符串）+ 动态分析（进程 / 文件 / 注册表 / 网络监控）

## 二、实验目的

1. 理解 Windows 平台恶意代码的典型行为：文件操作、进程操作、注册表操作、网络连接。
2. 掌握恶意代码静态分析方法：文件属性、PE 结构、导入表、字符串特征。
3. 掌握恶意代码动态分析方法：进程监控、文件系统监控、注册表监控、网络监控。
4. 掌握 Process Explorer、Process Monitor、TCPView、Strings 等工具的使用方法。
5. 建立恶意代码防治的基础安全意识。

## 三、实验原理（简要）

`malware_sim.c` 模拟了四类典型恶意行为：

- 文件行为：在临时目录创建伪装成 `svchost` 的可疑文件。
- 进程行为：打印自身 PID，创建子进程 `calc.exe`，随后终止。
- 注册表行为：向 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 写入启动项，实现持久化。
- 网络行为：建立到 `www.baidu.com:80` 的 TCP 连接。

静态分析不运行程序，通过文件元数据、PE 导入表和字符串判断程序能力；动态分析运行程序，通过 ProcMon、Process Explorer、TCPView 实时观察系统调用与网络活动。

## 四、实验内容与过程

### 4.1 编写并编译模拟恶意代码

1. 在 Visual Studio 中新建空项目 `malware_sim`，添加 `malware_sim.c`，粘贴教学代码。
2. 配置为 `Release` + `Win32`，并将项目字符集改为“使用多字节字符集”，添加预处理器定义 `_CRT_SECURE_NO_WARNINGS`。
3. 生成解决方案，得到 `malware_sim.exe`。

> 注意：若字符集保持 Unicode，`CreateProcess` 会被解析为 `CreateProcessW`，与代码中的 ANSI 类型不匹配，导致 Step 1 崩溃。

### 4.2 静态分析

- 文件基础信息与哈希：查看文件属性、数字签名，并使用 `Get-FileHash` 计算 MD5/SHA1/SHA256。
- PE 结构：使用 CFF Explorer 查看 `Import Directory`。
- 字符串提取：`strings.exe -a malware_sim.exe > strings.txt`，搜索敏感字符串。

### 4.3 动态分析

- 使用 Process Explorer 观察进程、父进程、TCP/IP、Strings、Security 等信息。
- 使用 Process Monitor 设置过滤器 `Process Name is malware_sim.exe then Include`，捕获文件、进程、注册表行为。
- 使用 TCPView 观察网络连接。

## 六、实验问题解答

### 6.1 静态分析结论

**问题 1：该程序导入了哪些关键 API？分别对应什么功能？**

- 文件操作：`CreateFileA`、`WriteFile`、`DeleteFileA`、`GetTempPathA` —— 在临时目录创建、写入并删除文件。
- 进程操作：`CreateProcessW`、`TerminateProcess`、`GetCurrentProcessId`、`CloseHandle` —— 创建、终止、管理进程。
- 注册表操作：`RegOpenKeyExA`、`RegSetValueExA`、`RegCloseKey` —— 写入自启动注册表项，实现持久化。
- 网络操作：`WSAStartup`、`getaddrinfo`、`socket`、`connect`、`closesocket`、`WSACleanup`、`freeaddrinfo` —— 解析域名并建立 TCP 连接。

**问题 2：在字符串中发现了哪些可疑信息？**

主要可疑信息包括：`svchost_update.tmp`、`SimulatedMalwareUpdate`、`Software\Microsoft\Windows\CurrentVersion\Run`、`www.baidu.com`、`calc.exe`、`This is a simulated malicious payload content.` 以及泄露编译路径的 `E:\Project\malware_sim\Release\malware_sim.pdb`。这些字符串分别指向文件伪装、注册表自启动、网络外联和进程创建行为。

### 6.2 动态分析结论

**问题 1：ProcMon 捕获到了哪些具体的文件创建、进程创建和注册表修改操作？请列出完整路径。**

- 文件创建：`C:\Users\baini\AppData\Local\Temp\svchost_update.tmp`。
- 进程创建：`C:\Windows\SysWOW64\calc.exe`。
- 注册表修改：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值名 `SimulatedMalwareUpdate`。

**问题 2：TCPView 显示程序尝试连接哪个 IP 和端口？状态是什么？**

程序连接 `www.baidu.com` 的 `80` 端口（TCP），状态为 `ESTABLISHED`，说明连接成功。实际解析出的 IP 以 TCPView 截图为准。

**问题 3：Process Explorer 中该进程的父进程是谁？**

父进程是 `powershell.exe`。本次实验是通过 Windows Terminal 中的 PowerShell 执行 `.\malware_sim.exe` 启动的，因此进程树为 `WindowsTerminal.exe → OpenConsole.exe → powershell.exe → malware_sim.exe`。实际以 Process Explorer 的 `Image` 标签页显示为准。

### 6.3 防治策略探讨

**问题 1：如果这是一款真正的木马，基于上述行为，主机防护软件（如 HIPS）应该在哪个环节拦截？**

关键拦截点按优先级为：

1. 注册表自启动写入：拦截对 `...\CurrentVersion\Run` 等自启动键的 `RegSetValue`，阻断持久化。
2. 网络外联：拦截非浏览器进程对可疑域名/IP 的对外连接，阻断命令与控制（C2）通信。
3. 进程创建：拦截可疑进程创建 `calc.exe` 等系统程序的异常启动行为。
4. 文件落盘：监控 `%TEMP%` 等目录中伪装成系统文件名的文件创建。

其中“注册表自启动写入”和“网络外联”是实现驻留与远控的核心环节，应优先拦截。

**问题 2：如何手动清除该模拟木马留下的痕迹（注册表项和文件）？**

- 删除注册表启动项：
  - 打开注册表编辑器，定位到 `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`。
  - 删除值 `SimulatedMalwareUpdate`。
  - 或使用命令：
    ```powershell
    Remove-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" -Name "SimulatedMalwareUpdate"
    ```
- 删除落盘文件：
  - 删除 `C:\Users\baini\AppData\Local\Temp\svchost_update.tmp`（即 `%TEMP%\svchost_update.tmp`）。
  - 实验结束后可同时删除 `E:\Project\malware_sim\Release\malware_sim.exe` 及其项目文件。

> 注意：程序自带清理逻辑只会删除临时文件 `svchost_update.tmp`，不会自动删除注册表 `Run` 项，因此注册表项必须手动清除。

## 七、实验总结

通过本次实验，完整走通了“编写模拟恶意代码 → 静态分析 → 动态分析”的流程。静态分析通过导入表和字符串判断出程序具备文件、进程、注册表、网络四类行为；动态分析用 ProcMon、Process Explorer、TCPView 实际捕获并验证了这些行为，与静态分析结论互相印证。实验进一步明确了恶意代码的典型行为特征，以及 HIPS 等主机防护软件应重点拦截的环节，增强了网络安全与恶意代码防治意识。
