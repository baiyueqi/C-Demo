## 三、实验基本原理

### 3.1 缓冲区溢出（栈溢出）漏洞原理

程序在栈空间申请固定长度字符缓冲区，未对用户输入长度进行边界合法性校验，使用 `strcpy`、无限制 `scanf` 等不安全函数。超长输入会依次覆盖缓冲区、栈局部变量、栈基址 EBP、函数返回地址，破坏栈帧结构，造成程序崩溃、执行流程异常、权限非法篡改。

### 3.2 SQL 注入漏洞原理

后端业务程序直接拼接用户可控输入构造 SQL 查询语句，未进行语法隔离与参数预处理。攻击者利用单引号闭合原有 SQL 语句结构，构造永真查询条件、注释截断后续语句，实现身份绕过、未授权登录、数据库敏感信息泄露。

## 4.5 漏洞作用机理

### 4.5.1 栈帧结构

`SystemLogin()` 调用 `UserVerify()` 后，`UserVerify()` 的栈帧大致如下：

```text
高地址
+--------------------------+
| 调用者数据、参数等        |
+--------------------------+
| 返回地址                 |  <- 覆盖后函数无法正常返回
+--------------------------+
| 旧的 EBP                 |  <- 覆盖后栈帧链被破坏
+--------------------------+
| verify_flag              |  <- 局部变量可能被覆盖
+--------------------------+
| pass_buffer[40]          |  <- strcpy 从这里开始写入
+--------------------------+
低地址
```

### 4.5.2 漏洞形成过程

1. `SystemLogin()` 使用 `scanf("%s", user_input)` 读取输入，没有限制输入长度。
2. `user_input` 的容量为 100 字节，但 `scanf("%s")` 不会阻止超过 99 个有效字符的输入。
3. `UserVerify()` 中的 `pass_buffer` 只有 40 字节，`strcpy()` 不检查目标缓冲区大小。
4. 当输入长度超过 `pass_buffer` 容量时，多余的字符继续写入栈中，依次覆盖局部变量、旧的 EBP 和函数返回地址。
5. 函数返回时读取到被破坏的返回地址，导致程序跳转到非法地址，从而崩溃或产生异常。

### 4.5.3 危害

- 程序异常退出，造成拒绝服务。
- 攻击者可能覆盖返回地址，劫持程序执行流程。
- 在缺少 DEP、ASLR 等防护的系统中，可能进一步实现任意代码执行。

## 4.6 安全修复源代码

修复思路：限制输入长度，使用带长度限制的字符串复制函数，并在关键逻辑处显式校验。

```c
#include <stdio.h>
#include <string.h>

int user_auth_level = 0;

int UserVerify(char *input_buf)
{
    char pass_buffer[40];
    int verify_flag = 0;

    if (strlen(input_buf) >= sizeof(pass_buffer))
    {
        return 0;
    }

    strncpy(pass_buffer, input_buf, sizeof(pass_buffer) - 1);
    pass_buffer[sizeof(pass_buffer) - 1] = '\0';

    if (strcmp(pass_buffer, "Admin@Sys2026Secure") == 0)
    {
        verify_flag = 1;
        user_auth_level = 1;
    }

    return verify_flag;
}

int SystemLogin()
{
    char user_input[100];
    printf("请输入系统登录密钥：");

    if (scanf("%99s", user_input) != 1)
    {
        return 0;
    }

    return UserVerify(user_input);
}

void AdminSystemOperate()
{
    printf("\n====================================\n");
    printf("      管理员权限：系统配置读写\n");
    printf("      日志导出、账户批量管理、后台运维\n");
    printf("====================================\n");
}

void NormalUserOperate()
{
    printf("\n[-] 普通用户权限，仅可查看基础信息\n");
}

int main()
{
    printf("======== 后台运维身份认证系统 V1.0 ========\n");
    int login_ret = SystemLogin();

    if (login_ret == 1)
    {
        printf("[登录成功]\n");
    }
    else
    {
        printf("[登录失败，密钥错误]\n");
    }

    if (user_auth_level >= 2)
    {
        AdminSystemOperate();
    }
    else
    {
        NormalUserOperate();
    }

    return 0;
}
```

## 4.8 综合防护措施

1. 使用安全的字符串处理函数，如 `strncpy`、`strlcpy`、`snprintf`。
2. 对用户输入进行长度校验，禁止无界输入。
3. 使用 `scanf` 时指定输入宽度，如 `%99s`。
4. 开启编译器栈保护 `/GS`。
5. 开启数据执行保护 `/NXCOMPAT`，并结合 ASLR。
6. 对关键变量进行冗余校验，避免单纯依赖局部认证变量。

## 5.5 SQL 注入攻击复现

### 攻击 1：任意密码登录

```text
用户名：admin'  or  '1'='1
密码：123
```

程序拼接出的 SQL 为：

```sql
SELECT * FROM user_info WHERE username='admin'  or  '1'='1' AND password='123'
```

由于 SQL 结构被篡改，条件恒为真，最终返回管理员账号。

> **截图 13：** 使用 `admin'  or  '1'='1` 绕过登录。
>
> ![截图13：OR 永真注入成功](screenshots/exp2_03_sqli_or_login_success.png)

### 攻击 2：万能密码登录

```text
用户名：' OR 1=1 -- 
密码：123
```

拼接后的 SQL 大致为：

```sql
SELECT * FROM user_info WHERE username='' OR 1=1 -- ' AND password='123'
```

`--` 将后面的密码判断注释掉，`1=1` 永远为真，因此直接登录管理员账号。

## 5.7 漏洞详细分析

### 漏洞 1：SQL 注入漏洞

- 产生原因：程序使用字符串拼接方式构造 SQL 语句，用户输入未经参数化处理。
- 攻击原理：攻击者利用单引号闭合原语句，注入 `OR 1=1`、`--` 等逻辑，改变 SQL 语义。
- 高危危害：身份认证被绕过、未授权访问、数据库信息泄露、数据被篡改或删除。

### 漏洞 2：密码明文存储

- 产生原因：数据库直接保存用户明文密码。
- 高危危害：一旦数据库文件泄露，攻击者可直接获取全部用户账号密码，造成更大范围的横向攻击和撞库风险。

## 5.8 漏洞修复实验

### 修复 1：参数化查询

```python
sql = "SELECT * FROM user_info WHERE username=? AND password=?"
cursor.execute(sql, (username, password))
```

参数化查询将用户输入作为数据而不是 SQL 代码处理，从根本上阻止注入。

### 修复 2：密码加盐哈希存储

```python
import hashlib
import hmac
import os


def hash_password(password, salt=None):
    if salt is None:
        salt = os.urandom(16)
    digest = hashlib.pbkdf2_hmac(
        'sha256',
        password.encode('utf-8'),
        salt,
        200_000
    )
    return salt.hex(), digest.hex()
```

数据库保存盐值和哈希值，登录时重新计算并比较，不再保存明文密码。

## 5.9 修复后完整安全代码

```python
import hashlib
import hmac
import os
import sqlite3

DB_NAME = 'secure_user_db.db'
PBKDF2_ITERATIONS = 200_000


def hash_password(password, salt=None):
    if salt is None:
        salt = os.urandom(16)
    digest = hashlib.pbkdf2_hmac(
        'sha256',
        password.encode('utf-8'),
        salt,
        PBKDF2_ITERATIONS
    )
    return salt.hex(), digest.hex()


def init_database():
    try:
        conn = sqlite3.connect(DB_NAME)
        cursor = conn.cursor()
        cursor.execute('''CREATE TABLE IF NOT EXISTS user_info
                        (username TEXT PRIMARY KEY,
                         salt TEXT NOT NULL,
                         password_hash TEXT NOT NULL,
                         role TEXT)''')

        users = [
            ('admin', 'Admin@2026', 'super_admin'),
            ('user1', '123456', 'normal_user'),
        ]

        for username, password, role in users:
            cursor.execute(
                "SELECT username FROM user_info WHERE username=?",
                (username,)
            )
            if cursor.fetchone() is None:
                salt, digest = hash_password(password)
                cursor.execute(
                    "INSERT INTO user_info VALUES (?,?,?,?)",
                    (username, salt, digest, role)
                )

        conn.commit()
    except Exception as e:
        print("初始化失败：", e)
    finally:
        if 'conn' in locals():
            conn.close()


def login(username, password):
    sql = "SELECT username, salt, password_hash, role FROM user_info WHERE username=?"
    print("执行SQL语句：", sql)

    try:
        conn = sqlite3.connect(DB_NAME)
        cursor = conn.cursor()
        cursor.execute(sql, (username,))
        row = cursor.fetchone()

        if row is None:
            return None

        username_db, salt_hex, hash_hex, role = row
        salt = bytes.fromhex(salt_hex)
        expected_hash = hash_password(password, salt)[1]

        if hmac.compare_digest(expected_hash, hash_hex):
            return username_db, role
        return None
    except Exception as e:
        print("数据库异常：", e)
        return None
    finally:
        if 'conn' in locals():
            conn.close()


if __name__ == '__main__':
    init_database()
    print("===== 安全修复版后台用户登录系统 =====")
    while True:
        user = input("请输入用户名：").strip()
        if user == 'exit':
            break

        pwd = input("请输入密码：").strip()

        if not user or not pwd:
            print("用户名或密码不能为空！")
            continue

        info = login(user, pwd)
        if info is not None:
            print("登录成功！欢迎进入系统后台")
            print("用户信息：", info)
            break
        else:
            print("用户名或密码错误，登录失败")
        print()
```

# 七、实验结论

## 7.1 缓冲区溢出漏洞

缓冲区溢出是典型的内存破坏漏洞，其根本原因是程序使用不安全函数且未对输入长度进行校验。攻击者通过超长输入破坏栈帧，可导致程序崩溃、控制流劫持，甚至任意代码执行。防护重点是长度校验、安全函数、编译器栈保护和数据执行保护。

## 7.2 SQL 注入漏洞

SQL 注入是典型的 Web 应用注入漏洞，其根本原因是用户输入被直接拼接进 SQL 语句，没有进行语法隔离。攻击者可以绕过身份认证、读取或篡改数据库内容。防护重点是参数化预编译查询、最小权限原则、密码加盐哈希存储和关闭详细错误回显。

## 7.3 两类漏洞的本质差异

| 比较项 | 缓冲区溢出 | SQL 注入 |
| --- | --- | --- |
| 漏洞类型 | 内存破坏漏洞 | 应用层注入漏洞 |
| 攻击对象 | 程序栈帧、内存控制流 | 数据库查询语句 |
| 主要危害 | 崩溃、控制流劫持、代码执行 | 认证绕过、数据泄露、数据篡改 |
| 核心修复 | 输入长度校验、安全函数、编译防护 | 参数化查询、输入隔离、安全存储 |

二者共同体现了不可信输入安全防护思想：所有外部输入都必须经过校验、限制或隔离后，才能进入程序的安全边界。
