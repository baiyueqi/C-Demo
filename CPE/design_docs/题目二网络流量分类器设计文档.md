# AI 驱动的网络流量分类器设计文档

## 1. 项目背景

本项目对应《计算机网络与通信》课程设计题目二：AI 驱动的网络流量分类器。

项目目标是实现一个能够捕获或读取网络数据包、提取网络流特征、使用机器学习模型判断流量类型的实验系统。系统需要体现计算机网络五层模型、抓包分析、协议字段解析和简单 AI 分类方法的结合。

本项目参考了《基本操作实验.pdf》中关于 `ipconfig`、`ping`、`tracert`、Wireshark、ARP、IP、TCP、UDP、DNS、HTTP 的实验内容，以及《Socket编程快速入门.pdf》中关于 IP、端口、协议、Socket 通信抽象和 TCP 连接过程的基础知识。

## 2. 设计目标

### 2.1 基本目标

1. 使用 Python 实现网络数据包捕获或读取。
2. 支持从 `.pcap` 文件读取数据包，降低实时抓包权限和环境风险。
3. 支持按五元组聚合网络流。
4. 从每条流中提取统计特征。
5. 使用简单机器学习模型对流量进行分类。
6. 输出流量类别和置信度。
7. 在报告中解释一个 HTTP 请求在五层模型中的封装和解封装过程。

### 2.2 扩展目标

1. 支持实时选择网卡抓包。
2. 抓取 100 个包后自动分类。
3. 检测简单攻击流量，例如 SYN Flood 和端口扫描。
4. 使用图形化界面显示流量类别随时间变化。

## 3. 技术选型

| 模块 | 选型 | 说明 |
| --- | --- | --- |
| 开发语言 | Python | 生态完整，适合快速实现抓包和机器学习 |
| 抓包工具 | Scapy | 可读取 pcap，也可实时抓包 |
| 数据处理 | pandas / 标准库 | 整理流和特征数据 |
| 机器学习 | scikit-learn | 训练决策树、KNN 或随机森林 |
| 模型保存 | joblib | 保存和加载训练后的模型 |
| 报告抓包验证 | Wireshark | 截图并分析五层封装过程 |

优先实现离线 `.pcap` 分析模式。实时抓包作为可选增强功能，因为实时抓包通常需要管理员权限，并且不同操作系统的网卡名称和权限配置不同。

## 5. 核心概念设计

### 5.1 五元组

网络流使用五元组标识：

```text
源 IP、目的 IP、源端口、目的端口、传输层协议
```

例如：

```text
192.168.1.10:51234 -> 93.184.216.34:443 TCP
```

为了避免同一连接的上下行方向被识别成两条完全不同的流，可以设计标准化五元组，将两个方向统一到同一条双向流中。

### 5.2 数据包字段

每个数据包需要提取以下基础字段：

| 层次 | 字段 |
| --- | --- |
| 链路层 | 源 MAC、目的 MAC、以太网类型 |
| 网络层 | 源 IP、目的 IP、TTL、IP 总长度、协议号 |
| 传输层 | TCP/UDP、源端口、目的端口、TCP flags |
| 应用层 | HTTP/DNS 等可识别协议标记 |

程序重点处理网络层和传输层字段，链路层和应用层字段主要用于报告解释和辅助分类。

## 6. 模块设计

### 6.1 数据包捕获模块

职责：

1. 读取 `.pcap` 文件。
2. 可选支持实时抓包。
3. 将原始数据包传递给协议解析模块。

建议接口：

```python
def load_packets_from_pcap(path: str) -> list:
    """Read packets from a pcap file."""

def capture_packets(interface: str, count: int = 100) -> list:
    """Capture packets from a network interface."""
```

### 6.2 协议解析模块

职责：

1. 判断数据包是否包含 IP 层。
2. 判断传输层协议是 TCP 还是 UDP。
3. 提取 IP、端口、TTL、包长、TCP 标志位等字段。
4. 忽略无法解析或不属于 TCP/UDP 的数据包。

输出结构示例：

```python
{
    "time": 1710000000.123,
    "src_ip": "192.168.1.10",
    "dst_ip": "93.184.216.34",
    "src_port": 51234,
    "dst_port": 443,
    "protocol": "TCP",
    "length": 1500,
    "ttl": 64,
    "tcp_flags": "PA"
}
```

### 6.3 流聚合模块

职责：

1. 按五元组将数据包归入不同网络流。
2. 统计每条流的包数量、字节数、持续时间等。
3. 保存每条流的到达时间列表和包长列表。

流对象示例：

```python
{
    "flow_id": ("192.168.1.10", "93.184.216.34", 51234, 443, "TCP"),
    "packets": [...],
    "start_time": 1710000000.123,
    "end_time": 1710000003.456
}
```

### 6.4 特征提取模块

每条流转换为一行特征数据。

基础特征：

| 特征 | 说明 |
| --- | --- |
| packet_count | 包数量 |
| total_bytes | 总字节数 |
| avg_packet_size | 平均包长 |
| max_packet_size | 最大包长 |
| min_packet_size | 最小包长 |
| duration | 流持续时间 |
| avg_interval | 平均到达间隔 |
| interval_variance | 到达间隔方差 |
| protocol | TCP/UDP 编码 |
| src_port | 源端口 |
| dst_port | 目的端口 |
| avg_ttl | 平均 TTL |
| syn_count | TCP SYN 数量 |
| ack_count | TCP ACK 数量 |
| fin_count | TCP FIN 数量 |

这些特征能对应课程要求中提到的平均包长、到达间隔方差、传输层协议、端口号、TTL 值等。

### 6.5 分类模块

训练阶段：

```text
标注数据集 -> 提取特征 -> 训练模型 -> 保存模型
```

预测阶段：

```text
新 pcap / 实时包 -> 提取特征 -> 加载模型 -> 输出类别和置信度
```

推荐模型：

1. 决策树：易实现，易解释，适合课程设计展示。
2. 随机森林：比单棵决策树更稳定，推荐作为最终模型。
3. KNN：简单，但预测时性能相对较弱。

输出示例：

```text
Flow 1: Web, confidence=0.87
Flow 2: DNS, confidence=0.92
Flow 3: P2P, confidence=0.64
```

## 7. 流量类别设计

建议先实现少量可验证类别：

| 类别 | 判断依据 |
| --- | --- |
| Web | TCP 80/443，包数量较多，双向通信明显 |
| DNS | UDP/TCP 53，包小，请求响应短 |
| SSH | TCP 22，长连接，包长中等 |
| ICMP | ping 流量，用于辅助实验分析 |
| Unknown | 无法确定或置信度较低 |

如果使用公开数据集，可以扩展为：

```text
Web、P2P、VoIP、Streaming、Game、VPN、Non-VPN、Attack
```

### 8.1 简化自采数据

可以使用 Wireshark 或 Scapy 采集以下流量并手动标注：

1. 浏览网页，标注为 Web。
2. 使用 `nslookup` 或浏览器触发 DNS 查询，标注为 DNS。
3. 使用 `ping`，标注为 ICMP。
4. 使用 SSH 连接，标注为 SSH。
5. 使用端口扫描工具生成扫描流量，标注为 PortScan。

### 8.2 公开数据集

公开数据集更正式，但字段处理和标签理解成本较高。课程设计中可以优先使用自采小数据集，再说明后续可扩展到公开数据集。

## 9. 五层模型分析设计

报告中需要详细解释一个 HTTP 请求从浏览器产生到被程序捕获的过程。

### 9.1 发送方向

```text
应用层：浏览器生成 HTTP 请求，例如 GET / HTTP/1.1
传输层：TCP 添加 TCP 头部，包括源端口、目的端口、序列号、确认号、标志位
网络层：IP 添加 IP 头部，包括源 IP、目的 IP、TTL、协议号
链路层：以太网添加帧头，包括源 MAC、目的 MAC、类型字段
物理层：转换为比特流，通过网线或无线信号发送
```

### 9.2 接收方向

```text
物理层：接收比特流
链路层：检查以太网帧，去除帧头
网络层：检查目的 IP，去除 IP 头部
传输层：根据端口交给对应进程，去除 TCP 头部
应用层：浏览器或服务器得到 HTTP 数据
```

### 9.3 程序捕获位置

Scapy 或 Wireshark 通常在操作系统网络协议栈附近捕获数据包。程序可以看到 IP、TCP/UDP、部分应用层内容，但通常不会直接处理物理层的电信号或无线信号。

## 10. 与基础实验内容的对应关系

| 基础实验内容 | 在本项目中的作用 |

| ARP 分析 | 解释跨网段访问时目的 MAC 是网关 |

| IP 分片 | 解释大包传输和 MTU 限制 |

| TCP 三次握手 | 理解 Web/SSH 等 TCP 流开始过程 |
| TCP 四次挥手 | 理解 TCP 流结束过程 |
| DNS 分析 | 识别 DNS 流量 |
| HTTP 分析 | 识别 Web 流量，并完成报告核心案例 |

## 11. 攻击检测扩展设计

### 11.1 SYN Flood

规则特征：

1. 短时间内出现大量 TCP SYN 包。
2. SYN 数量远大于 ACK 数量。
3. 目标 IP 和目标端口较集中。

简单判断规则：

```text
if syn_count > threshold and syn_count / max(ack_count, 1) > ratio:
    label = "SYN_Flood"
```

### 11.2 端口扫描

规则特征：

1. 同一个源 IP 访问同一个目的 IP 的多个端口。
2. 每个端口连接持续时间短。
3. SYN 包较多，实际数据包较少。

简单判断规则：

```text
if unique_dst_ports > threshold and avg_packets_per_port < small_value:
    label = "PortScan"
```

攻击检测可以作为机器学习分类之外的规则模块，降低实现难度。

## 12. 运行流程设计

### 12.1 离线模式

```text
1. 读取 pcap 文件
2. 解析 TCP/UDP/IP 数据包
3. 按五元组聚合为网络流
4. 提取每条流的统计特征
5. 加载模型
6. 输出每条流的类别和置信度
```

命令示例：

```bash
python main.py --mode offline --pcap samples/web_dns.pcap
```

### 12.2 实时模式

```text
1. 用户选择网卡
2. 抓取 100 个包
3. 聚合流并提取特征
4. 加载模型分类
5. 输出当前流量类别及置信度
```

命令示例：

```bash
python main.py --mode live --iface eth0 --count 100
```

## 15. 风险与解决方案

| 风险 | 解决方案 |
| --- | --- |
| 实时抓包需要管理员权限 | 优先支持离线 pcap 文件 |
| HTTPS 内容加密，无法读取应用层明文 | 使用端口、包长、时间间隔等统计特征 |
| 数据集标签不足 | 自采少量数据并手动标注 |
| 模型准确率不高 | 先减少类别数量，再逐步扩展 |
| 不同系统网卡名称不同 | 提供网卡列表或使用命令参数指定 |
| TCP 流有方向问题 | 使用标准化五元组合并双向流 |

## 18. 总结

本设计采用“抓包分析 + 流特征提取 + 机器学习分类”的方案完成 AI 驱动网络流量分类器。系统实现难度适中，能够覆盖课程设计要求中的网络五层模型、Wireshark 抓包、TCP/UDP 协议分析、HTTP 请求过程解释和 AI 分类模块。

在实现策略上，优先完成离线 pcap 分类，保证系统稳定可演示；再根据时间增加实时抓包、图形界面或攻击检测功能。
