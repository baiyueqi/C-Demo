## 题目一：共享数据库的并发访问控制（线程的同步/互斥）

### 题目背景与场景

某大型在线图书馆系统维护着一个共享的电子书数据库。该数据库支持两种并发操作：

1. **读者（Reader）**：可以同时多人阅读数据库中的电子书，统一为数据库的“读”操作，但读取过程中不允许有任何写操作进行。

2. **写者（Writer）**：负责更新、修改或删除数据库中的电子书，统一为数据库的“写”操作。写操作必须独占数据库，即当有写者在操作时，不允许任何其他读者或写者访问。

为了优化系统性能，图书馆引入了**“缓存区”机制**。缓存区可以存放N本最近被访问的电子书副本。读者在读取时，优先从缓存区读取；当缓存中没有所需书籍时，由一个监督模块读取数据库中对应内容到缓存，而后读者仍从缓存中读取。写者在更新书籍后，必须同步更新缓存区中的对应副本，以保证数据一致性。

### 实验目的

1. 掌握使用信号量（P、V操作）解决复杂的进程（线程）同步与互斥问题。
2. 学习如何将经典问题与实际应用场景（如缓存机制）相结合，进行系统设计。
3. 培养在Linux环境下使用C/C++和pthread库进行多线程编程的能力。

### 实验内容与要求

使用P、V操作（信号量）在Linux系统下，利用C/C++和pthread库，模拟实现上述共享数据库的并发访问控制。

#### 具体要求：

##### 1. 基本同步规则

- **读者优先**：当没有写者在操作时，多个读者可以同时进入数据库读取。但当一个读者正在读取时，写者必须等待。
- **写者独占**：当一个写者正在操作时，写操作必须独占整个数据库资源，期间禁止任何其他读者或写者的访问。

##### 2. 缓存区机制

为减少对主数据库的直接访问压力，系统引入一个大小为N（例如 N=5）的有界缓存区。

- **读者流程**：读取前，先查询缓存区。若缓存命中，则直接读取缓存副本；若未命中，则需等待并触发一次“缓存加载”操作——等待辅助线程将新数据加载进缓存区，然后再从缓存区读取。
- **缓存区命中判断**：**简单起见，可设置一个与缓存对应的数组BookNames[]，存放缓存中书的书名，若该书名与读者请求之书名一致，可视为命中**。
- **写者流程**：完成对主数据库的更新后，必须立即检查并更新缓存区中对应的数据副本，以确保后续读者读到的是最新数据。

##### 3. 缓存同步架构——生产者-消费者模式

应包含三个核心逻辑单元：

- **消费者单元（读者线程）**：仅负责等待并从缓存中读取数据，之后释放槽位。
- **生产者单元（缓存管理器线程）**：作为后台守护线程，持续监听，负责数据的预加载、填充的执行。**简单起见，可用一个全局变量临时存放读者请求的书名，读者、写者通过共享此变量来进行书名的传输。**
- **写者单元**：在修改主数据库后，保持数据一致性。

##### 4. 线程模型与模拟

- **线程配置**：指定固定数目的读者和写者，如创建M个读者线程（如 M=8）和K个写者线程（如 K=3）。
- **线程行为**：每个线程应循环执行其操作若干次（例如5次）后退出。每次数据的读、写、加载、刷新操作，可用sleep函数模拟耗时（1~5秒随机值）。
- **重要**：除上述数据读写处理操作外，所有的缓冲区结构操作（如队列操作、数组操作）必须是真实的操作，不允许用sleep模拟。
- **输出要求**：每个关键步骤（如读、加载缓存、更新缓存、写等）都应打印清晰的日志，以观察并发执行顺序和同步是否正确。

### 参考技术思路（不一定完全准确，只是一个思路，仅供参考，不必局限此思路）

#### 1. 变量设计（如果信号量初值设置不对，请自行修正）

| 信号量/变量 | 初值 | 作用 |
|------------|------|------|
| sem_t write | 1 | 写锁，实现写独占 |
| int read_count | 0 | 当前正在读的读者数 |
| sem_t read_mutex | 1 | 保护read_count的互斥锁 |
| string BookNames[] | {} | 存放被缓存的书的书名数组 |
| sem_t cache_mutex | 1 | 互斥访问缓存区数据结构 |
| sem_t empty | N | 缓存区空槽位数量 |
| sem_t full | 0 | 缓存区已占用数量 |
| struct BookReq[] | {} | 结构体（书名、读者id、请求位）数组 |
| sem_t book_mutex | 1 | 保护BookReq的互斥锁 |

**开始之前，思考**：如何在“读者线程（消费者）”和“监督模块：缓存管理器线程（生产者）”之间高效传递读者的请求信息？让监督模块准确、快速定位是哪位读者请求了哪本书？有什么优化的解决方案？

#### 2. 读者线程（消费者）伪代码

```
reader_thread() {
    // 每个读者应携带要请求的书名参数
    
    P(read_mutex);
    if (read_count == 0) P(write);   // 第一个读者，禁止写者
    read_count++;
    V(read_mutex);
    
    // 进入读取区，仅作为缓存消费者
    P(cache_mutex);                  // 获取缓存互斥锁
    if (该读者请求的书在缓存中命中) {
        从缓存读取数据;
        sleep(...);
        V(cache_mutex);
    } else {
        // 未命中，申请资源加载数据
        V(cache_mutex);              // 先释放锁，避免持锁等待
        
        P(book_mutex);
        将读者要求的书名刷新到对应的BookReq项;
        BookReq[]中对应项的请求位置1;
        V(book_mutex);
        
        P(full);                     // 等待缓存线程存入新数据
        P(cache_mutex);              // 重新获取缓存互斥锁
        从缓存读取新数据;
        sleep(...);
        V(empty);                    // 读取完成，释放一个缓冲区槽位
        V(cache_mutex);
    }
    
    P(read_mutex);
    read_count--;
    if (read_count == 0) V(write);   // 最后一个读者，允许写者
    V(read_mutex);
}
```

#### 3. 缓存管理器线程（生产者）伪代码

```
cache_manager_thread() {
    while(true) {
        P(book_mutex);
        接收消费者发送所请求的书名;
        获取BookReq[]中第一个请求位被置1的项;
        对应项的请求位被重新置为0;
        V(book_mutex);
        
        P(empty);                    // 等待一个空缓存槽位
        P(cache_mutex);              // 获取缓存互斥锁
        从数据库加载对应书的内容到缓存;
        sleep2(...);
        将要缓存的书的书名放入数组BookNames[];
        V(full);                     // 生产一个缓存项
        V(cache_mutex);
    }
}
```

#### 4. 写者线程伪代码

```
writer_thread() {
    // 每个写者应携带要写入的书名参数
    
    P(write);                        // 获取写锁，独占数据库
    
    // 进入写入区
    模拟写入主数据库操作;
    sleep3(...);
    
    P(empty);                        // 等待一个空缓存槽位
    P(cache_mutex);
    模拟更新缓存操作;
    sleep4(...);
    将要刷新的书的书名放入数组BookNames[];
    V(cache_mutex);
    V(full);                         // 成功放入缓存项
    
    V(write);                        // 释放写锁
}
```

> **提醒**：上述流程中，除标出的模拟操作函数sleep1~4外，其他所有链表操作（或数组操作）、标志位操作等，均必须是真实操作。

### 难点提示

**信号量交织与死锁避免**：本设计涉及多个信号量。必须严格设计PV操作的顺序（例如，获取资源锁的顺序），避免循环等待导致死锁。一个常见原则是：**在持有某个锁时，尽量避免等待另一个可能由其他线程持有的锁**。（以上示例伪代码未经真实代码检验，可能存在死锁风险，须避免。）

### 其他要求

- 编程语言要求：C/C++/C++ STL
- 推荐使用C++ STL，可方便实现缓冲区的各种操作

## 题目二：自定义Linux系统调用

### 实验内容

将题目一中所用到的用于模拟读、写、加载、刷新操作的随机sleep1~4函数改写成**4个新的Linux系统调用**，并在题目一中使用。

假设新系统调用最终可供用户使用的函数是`diag(int number)`，要求：
- 输入参数number是自己的学号（如2024*****）
- diag函数的功能定义为：以number为随机数种子，产生一个1000到5000之间的随机数字X；然后让程序等待X毫秒。

### 技术思路（仅供参考）

a) 增加新的Linux系统调用的方法 ，参考网上的参考资料。

b) 随机数的产生、程序等待函数的调用，参见Linux C语言函数库（自行学习）。

**大致步骤**：
1. 修改Linux内核某文件，将实现的函数名进行注册
2. 重新编译内核，使修改生效
3. 编写程序，调用内核函数（即系统调用）

> **注意**：本题可能涉及Linux内核编译，做该题目时，可对关键步骤进行截屏，以证实自己的过程。
