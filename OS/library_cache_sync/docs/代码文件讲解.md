# 代码文件讲解

本文按文件解释 `OS/library_cache_sync` 项目的代码，便于后续复习、报告撰写和验收答辩。

项目核心目标是模拟“共享电子书数据库”的并发访问控制：

1. 多个读者可以并发读取。
2. 写者必须独占数据库。
3. 读者先查有界缓存，缓存未命中时由缓存管理器加载。
4. 写者更新数据库后，如果缓存中已有对应副本，需要同步刷新缓存。
5. 题目二将读、加载、写、刷新四类延时替换为 Linux 自定义系统调用。

## 1. 顶层文件

### 1.1 `Makefile`

作用：负责编译、清理和运行用例。

关键变量：

```make
CXX ?= clang++
CPPFLAGS ?= -I include
CXXFLAGS ?= -std=c++17 -pthread -Wall -Wextra -O2
```

含义：

1. 使用 `clang++` 编译。
2. `-I include` 让源码可以直接 `#include "common.h"`。
3. `-pthread` 支持 pthread 和 POSIX semaphore。
4. `-Wall -Wextra` 打开常见警告。

普通目标：

```make
all
run-quick
run-demo
run-cache-one
run-writers-only
```

这些用于题目一普通用户态延时验证。

题目二目标：

```make
build-diag
run-diag-demo
run-diag-smoke
```

这些目标会加入：

```text
-DUSE_DIAG_SYSCALL
-D__NR_diag_read=548
-D__NR_diag_load=549
-D__NR_diag_write=550
-D__NR_diag_refresh=551
```

因此程序会优先调用自定义 Linux 系统调用。

验收讲法：

```text
Makefile 同时保留普通用户态验证和系统调用验证两条路径。默认 all 目标方便在普通环境运行，build-diag 目标用于启动自定义内核后验证题目二。
```

## 2. 公共头文件

### 2.1 `include/common.h`

作用：定义全局公共数据结构和 P/V 操作包装。

核心结构：

```cpp
struct Book {
    std::string name;
    std::string content;
    int version;
};
```

`Book` 表示一本电子书：

1. `name` 是书名。
2. `content` 是内容。
3. `version` 是版本号，用来观察写者更新后数据是否变化。

配置结构：

```cpp
struct Config {
    int readers = 8;
    int writers = 3;
    int cache_size = 5;
    int rounds = 5;
    long long student_no = 20241001655LL;
    int delay_min_ms = 1000;
    int delay_max_ms = 5000;
    unsigned int random_seed = 0;
};
```

它保存程序运行参数，比如读者数、写者数、缓存容量、循环轮数、学号和随机种子。

P/V 包装：

```cpp
inline void P(sem_t* sem)
inline void V(sem_t* sem)
```

含义：

1. `P` 对应 `sem_wait`，申请资源。
2. `V` 对应 `sem_post`，释放资源。
3. `P` 会处理 `EINTR`，避免信号打断导致错误退出。

验收讲法：

```text
common.h 中把题目要求的 P/V 操作封装成函数，后续所有同步都通过 P 和 V 表达，便于对应操作系统课里的信号量概念。
```

## 3. 数据库模块

### 3.1 `include/database.h`

作用：声明主数据库类 `Database`。

主要接口：

```cpp
Book readBook(const std::string& name) const;
Book writeBook(const std::string& name, int writer_id);
std::vector<std::string> allBookNames() const;
```

含义：

1. `readBook` 从主数据库读取一本书。
2. `writeBook` 更新一本书，并提升版本号。
3. `allBookNames` 返回所有书名，供读者和写者随机选择。

### 3.2 `src/database.cpp`

作用：实现模拟主数据库。

初始化数据：

```text
OS
Linux
Database
Compiler
Network
Security
Algorithm
```

读操作：

```cpp
Book Database::readBook(const std::string& name) const
```

根据书名查找并返回副本。如果书不存在，抛出异常。

写操作：

```cpp
Book Database::writeBook(const std::string& name, int writer_id)
```

执行三件事：

1. 找到目标书。
2. `version++`。
3. 更新 `content`，记录由哪个写者更新。

注意：`Database` 自己不加锁，数据库访问的互斥由 `Simulator` 中的 `db_sem` 统一控制。

验收讲法：

```text
主数据库是真实的 map 数据结构，不是简单 sleep。写者更新会让版本号递增，后续日志可以看到 version=2、version=3 等变化。
```

## 4. 缓存模块

### 4.1 `include/cache.h`

作用：声明有界缓存 `Cache` 和缓存槽 `CacheEntry`。

缓存槽结构：

```cpp
struct CacheEntry {
    bool valid = false;
    Book book;
    unsigned long last_access_tick = 0;
    std::set<int> pinned_request_ids;
};
```

字段含义：

1. `valid` 表示槽位是否已经存放书籍。
2. `book` 是缓存中的电子书副本。
3. `last_access_tick` 用于 LRU 替换。
4. `pinned_request_ids` 用于保护刚加载但还没被读者复制的缓存项。

关键接口：

```cpp
bool findAndCopy(...);
bool updateExistingAndPin(...);
void insertIntoFreeSlotAndPin(...);
bool replaceLruAndPin(...);
void releasePin(...);
bool updateIfPresent(...);
std::string snapshot() const;
```

### 4.2 `src/cache.cpp`

作用：实现缓存查询、插入、替换、刷新和日志快照。

缓存命中：

```cpp
bool Cache::findAndCopy(const std::string& name, Book& out)
```

遍历缓存槽，如果找到同名书：

1. 更新 `last_access_tick`。
2. 把书复制到 `out`。
3. 返回 `true`。

缓存加载：

如果缓存中已有目标书：

```cpp
updateExistingAndPin(...)
```

如果有空槽：

```cpp
insertIntoFreeSlotAndPin(...)
```

如果缓存已满：

```cpp
replaceLruAndPin(...)
```

LRU 替换只会选择没有 pin 的缓存项：

```text
未被 pin 的最久未访问项才允许被替换
```

pin 的意义：

当读者缓存 miss 后，缓存管理器把书加载到缓存，并给该请求加 pin。这样在读者被唤醒并复制数据之前，这个缓存项不会被另一个请求淘汰。

释放 pin：

```cpp
releasePin(...)
```

读者复制完成后调用，表示该缓存项可以再次参与替换。

验收讲法：

```text
缓存区是真实的有界数组。容量满时使用 LRU 替换，同时通过 pin 集合保护刚加载的数据，避免读者还没复制就被其他加载请求淘汰。
```

## 5. 请求队列模块

### 5.1 `include/request_queue.h`

作用：声明读者缓存 miss 后提交给缓存管理器的请求。

请求结构：

```cpp
struct LoadRequest {
    Type type;
    int reader_id;
    std::string book_name;
    int request_id;
};
```

字段含义：

1. `type` 区分普通请求和 shutdown 请求。
2. `reader_id` 表示哪个读者发起请求。
3. `book_name` 表示要加载哪本书。
4. `request_id` 是请求唯一编号，用于和缓存 pin 对应。

### 5.2 `src/request_queue.cpp`

作用：实现队列的 push 和 pop。

```cpp
void RequestQueue::push(const LoadRequest& req)
bool RequestQueue::pop(LoadRequest& req)
```

注意：`RequestQueue` 本身不加锁，锁由 `Simulator` 中的 `request_mutex` 统一控制。

验收讲法：

```text
题目参考里允许用全局变量传书名，但本项目使用请求队列保存 reader_id、book_name 和 request_id，避免多个读者同时 miss 时请求互相覆盖。
```

## 6. 延时模块

### 6.1 `src/delay.cpp`

作用：封装四类模拟耗时函数。

对外接口：

```cpp
void delay_read(long long student_no);
void delay_load(long long student_no);
void delay_write(long long student_no);
void delay_refresh(long long student_no);
```

普通编译时：

```cpp
user_delay(...)
```

使用用户态随机数和 `sleep_for`，方便普通环境运行题目一。

题目二编译时：

```cpp
syscall(__NR_diag_read, student_no);
syscall(__NR_diag_load, student_no);
syscall(__NR_diag_write, student_no);
syscall(__NR_diag_refresh, student_no);
```

也就是说，只要编译时定义 `USE_DIAG_SYSCALL` 和 4 个系统调用号，延时函数就会进入内核。

验收讲法：

```text
题目一主程序不需要改业务逻辑，只需要通过 delay.cpp 这一层把延时实现从用户态 sleep 切换为 Linux 自定义系统调用。
```

## 7. 模拟器模块

### 7.1 `include/simulator.h`

作用：声明整个并发模拟系统。

核心成员：

```cpp
Database database_;
Cache cache_;
RequestQueue request_queue_;
```

表示主数据库、缓存区和加载请求队列。

核心信号量：

```cpp
sem_t db_sem_;
sem_t read_mutex_;
sem_t cache_mutex_;
sem_t empty_slots_;
sem_t full_slots_;
sem_t cache_unpinned_;
sem_t request_mutex_;
sem_t request_count_;
sem_t log_mutex_;
std::vector<sem_t> reader_ready_;
```

含义：

1. `db_sem_` 控制读者与写者对数据库的互斥。
2. `read_mutex_` 保护 `read_count_`。
3. `cache_mutex_` 保护缓存区。
4. `empty_slots_` 和 `full_slots_` 体现有界缓存容量。
5. `cache_unpinned_` 在缓存满且全部被保护时用于等待。
6. `request_mutex_` 保护请求队列。
7. `request_count_` 表示待处理请求数量。
8. `reader_ready_` 用于缓存管理器唤醒指定读者。
9. `log_mutex_` 保证日志不交叉。

### 7.2 `src/simulator.cpp`

作用：实现项目最核心的并发逻辑。

#### 7.2.1 初始化

构造函数初始化所有信号量：

```text
db_sem_ = 1
read_mutex_ = 1
cache_mutex_ = 1
empty_slots_ = cache_size
full_slots_ = 0
request_count_ = 0
```

#### 7.2.2 启动线程

`Simulator::run()` 创建：

1. 一个缓存管理器线程。
2. 多个读者线程。
3. 多个写者线程。

读者和写者结束后，主线程发送 shutdown 请求，让缓存管理器退出。

#### 7.2.3 读者线程

读者一轮流程：

```text
选择一本书
进入读区
查询缓存
命中：复制缓存副本
未命中：提交加载请求，等待 reader_ready
执行 delay_read
离开读区
```

读者优先由：

```text
read_count_ + read_mutex_ + db_sem_
```

实现。

#### 7.2.4 写者线程

写者一轮流程：

```text
选择一本书
P(db_sem_)
更新主数据库
执行 delay_write
如果缓存有副本，刷新缓存
执行 delay_refresh
V(db_sem_)
```

因为写者必须获得 `db_sem_`，所以写者不会和读者或其他写者同时访问数据库。

#### 7.2.5 缓存管理器线程

缓存管理器循环等待请求：

```text
P(request_count_)
从 request_queue_ 取请求
从数据库读书
执行 delay_load
写入或替换缓存
V(reader_ready_[reader_id])
```

它是生产者，读者是消费者。读者产生加载请求，缓存管理器消费请求并生产缓存副本。

#### 7.2.6 日志

`logLine()` 用 `log_mutex_` 保护输出，避免多个线程同时打印导致日志混在一起。

验收讲法：

```text
Simulator 是整个同步设计的核心。读者-写者问题、生产者-消费者问题、有界缓存区、日志输出和线程生命周期都在这里统一调度。
```

## 8. 用户态系统调用验证程序

### 8.1 `syscall/user_call_demo.cpp`

作用：单独验证 4 个自定义系统调用是否可用。

它不运行完整主程序，只按顺序调用：

```text
diag_read
diag_load
diag_write
diag_refresh
```

每个调用都会打印：

```text
函数名
返回值
耗时毫秒数
```

如果输出：

```text
returned 0
elapsed_ms=1000 到 5000 左右
```

说明系统调用成功。

验收讲法：

```text
user_call_demo 用于排除主程序同步逻辑干扰，单独证明 548 到 551 四个系统调用都能从用户态调用到内核。
```

## 9. 完整运行流程串联

以 `--seed 2` 用例为例：

```text
Reader-01 request OS
Reader-01 cache miss OS
CacheManager load OS
Reader-01 read OS version=1
Writer-01 update OS version=2
Writer-01 refresh cache OS version=2
Main finished
```

对应四个系统调用：

```text
CacheManager load OS       -> diag_load
Reader-01 read OS          -> diag_read
Writer-01 update OS        -> diag_write
Writer-01 refresh cache OS -> diag_refresh
```

## 10. 设计特点和可说明的优化

1. 使用请求队列，而不是单个全局书名变量，避免并发请求覆盖。
2. 使用 `reader_ready_` 数组，准确唤醒发起请求的读者。
3. 使用 LRU 替换，缓存满时替换最久未访问的副本。
4. 使用 pin 保护，防止刚加载的数据被提前淘汰。
5. 使用统一的 `delay.cpp` 封装，让题目一和题目二共享同一套业务逻辑。

## 11. 存在的问题和改进方向

1. 当前是读者优先，持续读者到来时写者可能饥饿。可改为公平读写锁。
2. 缓存管理器只有一个线程，多个 miss 会排队处理。可扩展为多个缓存管理器线程。
3. `Database` 和 `RequestQueue` 自身不加锁，依赖 `Simulator` 外部统一加锁。这样结构清晰，但调用者必须遵守锁约定。
4. 系统调用路径失败时会 fallback 到用户态延时。验收时必须结合 `dmesg` 证明确实进入内核。
5. 当前缓存是“最近访问副本池”，读者读完不会删除缓存项，因此和传统一次性生产者-消费者缓冲区略有区别。报告中应说明这是为了符合电子书缓存语义。

## 12. 验收时的总述

可以这样总结：

```text
本项目用 pthread 和 POSIX semaphore 模拟在线图书馆共享电子书数据库。读者优先由 read_count、read_mutex 和 db_sem 实现，写者通过 db_sem 独占数据库。读者读取前先查有界缓存，缓存未命中时提交加载请求，缓存管理器线程从数据库加载书籍并放入缓存。缓存满时使用 LRU 替换，并用 pin 防止刚加载的数据在读者复制前被淘汰。写者更新数据库后，如果缓存中存在对应副本，会同步刷新缓存。题目二中，读、加载、写、刷新四类延时通过 delay.cpp 切换为 548 到 551 四个 Linux 自定义系统调用，并通过 user_call_demo、主程序日志和 dmesg 验证成功。
```
