# 题目二逐步操作：自定义 Linux 系统调用

本文按“在 Ubuntu 虚拟机或课程指定 Linux 环境中修改内核”的方式写。当前仓库所在的 NixOS 工作区适合编译用户态程序，不建议直接在 NixOS 主机上用 `make install` 替换系统内核。

本文采用 4 个系统调用方案：

```text
delay_read    -> diag_read(number)
delay_load    -> diag_load(number)
delay_write   -> diag_write(number)
delay_refresh -> diag_refresh(number)
```

每个系统调用接收学号 `number`，生成 1000 到 5000 毫秒的等待时间，并让当前进程睡眠。这样正好对应题目一中的读、加载、写、刷新四类模拟耗时。

## 适用于 WSL 和 NixOS 的选择

如果你现在只有 WSL 和 NixOS，建议按下面优先级选择：

1. 优先用 WSL2 + Ubuntu 发行版完成题目二。WSL2 支持加载自定义 Linux 内核，适合做系统调用实验。
2. 不建议直接在 NixOS 主机上改系统内核。NixOS 的内核管理方式和普通 Ubuntu 不同，课程验收截图也不如 Ubuntu/WSL2 直观。
3. 如果老师明确不接受 WSL2，就在 NixOS 上安装 VirtualBox、VMware、GNOME Boxes 或 virt-manager，再建一个 Ubuntu 虚拟机，按本文后续普通 Ubuntu 流程做。

检查 WSL 版本，在 Windows PowerShell 里执行：

```powershell
wsl -l -v
```

如果你的 Ubuntu 不是 VERSION 2，先转换：

```powershell
wsl --set-version Ubuntu 2
```

如果当前没有 Ubuntu WSL，建议安装一个 Ubuntu WSL 专门做实验，不要用 NixOS WSL 做内核课程设计：

```powershell
wsl --install Ubuntu
```

WSL2 和普通虚拟机的区别是：WSL2 不通过 grub 选择内核，也不使用 `sudo make install` 安装内核；它通过 Windows 用户目录下的 `.wslconfig` 指向自定义 `bzImage`。

WSL2 专用启动新内核步骤如下：

1. 在 WSL2 Ubuntu 中编译出：

```text
arch/x86/boot/bzImage
```

2. 复制到 Windows 用户目录，例如：

```bash
mkdir -p /mnt/c/Users/<你的Windows用户名>/wsl-kernels
cp arch/x86/boot/bzImage /mnt/c/Users/<你的Windows用户名>/wsl-kernels/bzImage-diag
```

3. 在 Windows PowerShell 中编辑：

```powershell
notepad $env:USERPROFILE\.wslconfig
```

写入：

```ini
[wsl2]
kernel=C:\\Users\\<你的Windows用户名>\\wsl-kernels\\bzImage-diag
```

4. 关闭并重启 WSL：

```powershell
wsl --shutdown
wsl
```

5. 在 WSL 中确认内核已切换：

```bash
uname -r
dmesg | grep diag_
```

如果你采用 WSL2 路线，下面第 6 步中的 `sudo make modules_install`、`sudo make install`、`sudo update-grub` 可以跳过，改用本节 `.wslconfig` 方式启动自定义内核。

## 0. 准备环境

建议使用 Ubuntu 虚拟机完成，先给虚拟机做快照。内核编译可能占用数 GB 空间，建议磁盘至少预留 30 GB。

安装依赖：

```bash
sudo apt update
sudo apt install -y build-essential bc bison flex libssl-dev libelf-dev \
  libncurses-dev dwarves rsync git fakeroot
```

安装内核源码包：

```bash
sudo apt install -y linux-source
```

创建实验目录并解压源码：

```bash
mkdir -p ~/kernel-lab
cd ~/kernel-lab
tar -xf /usr/src/linux-source-*.tar.*
cd linux-source-*
```

查看当前内核版本，后面报告截图可以用：

```bash
uname -r
```

## 1. 准备内核配置

复制当前系统的内核配置：

```bash
cp /boot/config-$(uname -r) .config
```

给自定义内核加一个后缀，便于重启后确认自己进入了新内核：

```bash
scripts/config --set-str LOCALVERSION "-diag"
```

Ubuntu 的配置里有时会引用本机没有的证书文件，清空这两个配置可以避免编译报证书缺失：

```bash
scripts/config --set-str SYSTEM_TRUSTED_KEYS ""
scripts/config --set-str SYSTEM_REVOCATION_KEYS ""
```

补齐默认配置：

```bash
make olddefconfig
```

查看最终内核版本名：

```bash
make kernelrelease
```

记下输出，例如：

```text
6.x.x-diag
```

## 2. 新增系统调用实现文件

新建文件：

```bash
nano kernel/diag.c
```

写入下面内容：

```c
#include <linux/delay.h>
#include <linux/printk.h>
#include <linux/syscalls.h>

static unsigned int diag_delay_ms(long number, int offset)
{
    unsigned long x = (unsigned long)number;

    x += (unsigned long)(offset * 1009);
    x ^= x << 13;
    x ^= x >> 17;
    x ^= x << 5;

    return 1000 + (x % 4001);
}

static long diag_delay_impl(long number, int offset, const char *name)
{
    unsigned int delay_ms = diag_delay_ms(number, offset);

    pr_info("%s(number=%ld) sleep %u ms\n", name, number, delay_ms);
    msleep(delay_ms);
    return 0;
}

SYSCALL_DEFINE1(diag_read, long, number)
{
    return diag_delay_impl(number, 1, "diag_read");
}

SYSCALL_DEFINE1(diag_load, long, number)
{
    return diag_delay_impl(number, 2, "diag_load");
}

SYSCALL_DEFINE1(diag_write, long, number)
{
    return diag_delay_impl(number, 3, "diag_write");
}

SYSCALL_DEFINE1(diag_refresh, long, number)
{
    return diag_delay_impl(number, 4, "diag_refresh");
}
```

说明：

1. `SYSCALL_DEFINE1` 表示系统调用有 1 个参数。
2. `msleep(delay_ms)` 是内核里的睡眠函数。
3. `pr_info` 会把调用记录写入内核日志，后面可用 `dmesg` 验证。

## 3. 把新文件加入内核编译

编辑：

```bash
nano kernel/Makefile
```

在合适位置追加一行：

```make
obj-y += diag.o
```

保存后可检查：

```bash
grep 'diag.o' kernel/Makefile
```

## 4. 声明系统调用函数

编辑：

```bash
nano include/linux/syscalls.h
```

在文件末尾 `#endif` 之前加入：

```c
asmlinkage long sys_diag_read(long number);
asmlinkage long sys_diag_load(long number);
asmlinkage long sys_diag_write(long number);
asmlinkage long sys_diag_refresh(long number);
```

检查：

```bash
grep 'sys_diag_' include/linux/syscalls.h
```

## 5. 注册系统调用号

编辑 x86_64 系统调用表：

```bash
nano arch/x86/entry/syscalls/syscall_64.tbl
```

先查看末尾已有编号：

```bash
tail -n 30 arch/x86/entry/syscalls/syscall_64.tbl
```

选择 4 个没有被占用的连续编号。下面用 `548` 到 `551` 举例，实际必须以你文件里的空号为准：

```text
548 common diag_read    sys_diag_read
549 common diag_load    sys_diag_load
550 common diag_write   sys_diag_write
551 common diag_refresh sys_diag_refresh
```

保存后检查：

```bash
grep 'diag_' arch/x86/entry/syscalls/syscall_64.tbl
```

把你实际使用的 4 个编号记下来，后面编译用户态程序要用。

## 6. 编译内核

开始编译：

```bash
make -j$(nproc) bzImage modules
```

这一步耗时较长。成功后安装模块和内核：

```bash
sudo make modules_install
sudo make install
```

更新 grub：

```bash
sudo update-grub
```

重启：

```bash
sudo reboot
```

如果重启后没有自动进入新内核，在 grub 菜单里选择带 `-diag` 后缀的内核。

## 7. 确认进入新内核

重启后执行：

```bash
uname -r
```

输出应包含前面设置的后缀：

```text
...-diag
```

如果没有 `-diag`，说明没有启动到新内核，需要从 grub 里重新选择。

## 8. 用题目一程序调用新系统调用

进入本项目目录：

```bash
cd /home/nixos/workspace/C-Demo
```

如果是在虚拟机里做内核实验，需要先把本项目复制到虚拟机中，然后进入对应目录。

假设你注册的系统调用号是：

```text
diag_read    = 548
diag_load    = 549
diag_write   = 550
diag_refresh = 551
```

则这样重新编译题目一程序：

```bash
make -C OS/library_cache_sync clean

make -C OS/library_cache_sync \
  CXXFLAGS="-std=c++17 -pthread -Wall -Wextra -O2 -DUSE_DIAG_SYSCALL \
  -D__NR_diag_read=548 -D__NR_diag_load=549 \
  -D__NR_diag_write=550 -D__NR_diag_refresh=551"
```

如果你的编号不是 `548` 到 `551`，把上面 4 个宏改成你自己的编号。

运行快速用例：

```bash
make -C OS/library_cache_sync run-quick
```

这时程序里的 `delay_read`、`delay_load`、`delay_write`、`delay_refresh` 会优先调用你新增的系统调用。

## 9. 查看内核日志验证

运行题目一程序后，查看内核日志：

```bash
dmesg | grep diag_
```

应能看到类似输出：

```text
diag_read(number=20241001655) sleep 2345 ms
diag_load(number=20241001655) sleep 3180 ms
diag_write(number=20241001655) sleep 1402 ms
diag_refresh(number=20241001655) sleep 4977 ms
```

这可以证明用户程序确实进入了内核系统调用，而不是普通用户态 `sleep`。

## 11. 验收讲解话术

可以这样讲：

```text
题目一中原来有四类模拟耗时函数：读、加载、写、刷新。
题目二要求把这些随机 sleep 改成 Linux 系统调用。
我在内核中新增了 diag_read、diag_load、diag_write、diag_refresh 四个系统调用，
它们都接收学号 number，根据 number 和操作类型生成 1000 到 5000 毫秒的延时，
然后在内核中调用 msleep。

用户态程序重新编译时定义 USE_DIAG_SYSCALL 和四个系统调用号，
delay_read/load/write/refresh 就会通过 syscall() 进入内核。
dmesg 中能看到 diag_read 等日志，证明不是普通用户态 sleep。
```

## 12. 常见问题

编译时报证书文件找不到：

```text
No rule to make target 'debian/canonical-certs.pem'
```

重新执行：

```bash
scripts/config --set-str SYSTEM_TRUSTED_KEYS ""
scripts/config --set-str SYSTEM_REVOCATION_KEYS ""
make olddefconfig
```

运行用户程序时报 `Function not implemented`：

1. 没有启动到新内核。
2. 系统调用号写错。
3. `syscall_64.tbl` 没注册成功。
4. 用户态编译时 `-D__NR_diag_xxx=<number>` 写错。

检查顺序：

```bash
uname -r
grep 'diag_' ~/kernel-lab/linux-source-*/arch/x86/entry/syscalls/syscall_64.tbl
dmesg | grep diag_
```

`dmesg` 没有日志：

1. 用户程序可能没有启用 `-DUSE_DIAG_SYSCALL`。
2. 程序可能走了 fallback 用户态延时。
3. 系统调用号宏和内核注册号不一致。

## 13. 如果老师要求统一 diag 名称

有些题目表述会提到最终用户函数名 `diag(int number)`。当前学号 `20241001655` 超过 32 位 `int` 范围，因此实际实现建议使用 `long number` 或 `long long number`，避免学号在内核日志中被截断。如果老师坚持只看 `diag` 这个名字，有两种处理方式：

1. 解释当前方案：内核中是 4 个系统调用，用户态四个 delay 函数分别调用对应系统调用，符合“sleep1 到 sleep4 改写成 4 个新系统调用”的要求。
2. 兼容方案：额外注册一个 `diag(long number)` 系统调用，用户态用 `diag(student_no + offset)` 区分读、加载、写、刷新。

当前项目默认走第 1 种方案。`syscall/user_call_demo.cpp` 用于直接验证 `diag_read/load/write/refresh` 四个系统调用；题目一主程序也使用这 4 个系统调用方案。
